# Phase 03.4 Plan 01: Geographic Org Auto-Assignment (NF-03-B) Summary

**One-liner:** Auto-assigns the matching BBMP corporation org to each new report via ward geography ILIKE join, records a system audit trail entry (changed_by=NULL, status=open), and fixes the admin CORP column to show the full org name via assigned_org_id JOIN.

## What Was Built

Closes UAT gap NF-03-B (major): reports were unrouted until manual admin assignment; the CORP column showed raw geography strings like "Central" instead of "Bengaluru Central Corporation".

### Task 1: SQL-string unit tests (RED)

- `get_org_for_ward_uses_ilike_and_org_type_filter` — asserts ILIKE pattern and org_type filter in queries.rs
- `list_admin_reports_corp_join_uses_assigned_org_id` — asserts LEFT JOIN organizations on assigned_org_id, NOT wards.corporation, in admin_queries.rs
- `auto_assign_history_sql_uses_open_status_and_null_changed_by` — asserts 'open' status, NULL changed_by, 'ward geography' note in admin_queries.rs

### Task 2: get_org_for_ward + insert_report (GREEN)
- New `pub async fn get_org_for_ward(pool: &PgPool, ward_id: Uuid) -> Result<Option<Uuid>, AppError>` added immediately after `get_ward_for_point` in queries.rs
- SQL: `SELECT o.id FROM wards w JOIN organizations o ON o.org_type = 'corporation' AND o.name ILIKE '%' || w.corporation || '%' WHERE w.id = $1 LIMIT 1`
- `insert_report` gains 5th parameter `assigned_org_id: Option<Uuid>`, INSERT column list gains `assigned_org_id`, VALUES gains `$13`, bind chain gains `.bind(assigned_org_id)`

- `list_admin_reports` SQL: `wards.corporation AS corporation` replaced with `o.name AS corporation`, `LEFT JOIN organizations o ON o.id = reports.assigned_org_id` added after wards JOIN

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] execute(&*state.pool) — Arc<PgPool> deref for sqlx Executor trait**
- **Found during:** Task 3 — cargo check
- **Issue:** `sqlx::query().execute(&state.pool)` failed with `the trait bound &Arc<Pool<Postgres>>: Executor<'_> is not satisfied`. `state.pool` is `Arc<PgPool>`, but sqlx's Executor trait is implemented for `&PgPool`, not `&Arc<PgPool>`. Auto-deref coercion works for the `queries::*` functions (they take `pool: &PgPool` which triggers Deref), but not for the raw `execute()` call.
- **Fix:** Changed to `execute(&*state.pool)` to explicitly deref the Arc to `&PgPool`
- **Files modified:** `backend/src/handlers/reports.rs`
- **Commit:** a83bfd8
