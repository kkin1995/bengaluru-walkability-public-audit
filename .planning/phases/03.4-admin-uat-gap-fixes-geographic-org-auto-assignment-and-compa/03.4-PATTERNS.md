pub async fn get_ward_for_point(
    pool: &PgPool,
    lat: f64,
    lng: f64,
) -> Result<Option<Uuid>, AppError> {
    let row = sqlx::query_as::<_, (Uuid,)>(
        r#"
        SELECT id FROM wards
        WHERE ST_Within(
            ST_SetSRID(ST_MakePoint($2, $1), 4326),
            boundary
        )
        LIMIT 1
        "#,
    )
    .bind(lat)
    .bind(lng)
    .fetch_optional(pool)
    .await?;

}

**New function to copy from this pattern:**
```rust
// Place immediately after get_ward_for_point in queries.rs
pub async fn get_org_for_ward(pool: &PgPool, ward_id: Uuid) -> Result<Option<Uuid>, AppError> {
    let row = sqlx::query_as::<_, (Uuid,)>(
        r#"
        SELECT o.id
        FROM wards w
        JOIN organizations o
          ON o.org_type = 'corporation'
          AND o.name ILIKE '%' || w.corporation || '%'
        WHERE w.id = $1
        LIMIT 1
        "#,
    )
    .bind(ward_id)
    .fetch_optional(pool)
    .await?;
    Ok(row.map(|(id,)| id))
}
```

**Key differences from the analog:**
- Single `$1` bind (ward_id: Uuid) instead of two floats
- JOIN pattern replaces the ST_Within PostGIS check
- Return type is identical: `Result<Option<Uuid>, AppError>`

**Error handling pattern** — same as `get_ward_for_point`: `?` on `.await`, returns `AppError` via the `From<sqlx::Error>` impl. No manual error mapping needed.

- Error is logged as `warn` and swallowed, not propagated
