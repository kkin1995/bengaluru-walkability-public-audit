### Human Verification Required

The automated code checks all pass and the code is fully wired. Four items require a live environment to confirm end-to-end behavior:

#### 1. Mobile Tap Navigation (NF-03-A)

**Test:** Open the admin reports list on a mobile viewport (or Chrome DevTools mobile mode). Switch to ROWS view. Tap anywhere on a report card body (not the Status or Delete buttons).
**Expected:** Browser navigates to `/admin/reports/:id` for that report. The detail page loads.
**Why human:** `window.location.assign` in a JSDOM test environment cannot simulate real browser navigation. The code path is correct and unit-tested via the sr-only anchor assertion, but actual navigation requires a browser.

#### 2. Org Auto-Assignment on Report Creation (NF-03-B SC#1)

**Test:** Submit a new report with coordinates inside a known Bengaluru ward (e.g. lat: 12.9716, lng: 77.5946 for Central). Then run: `SELECT r.assigned_org_id, o.name FROM reports r JOIN organizations o ON o.id = r.assigned_org_id ORDER BY r.created_at DESC LIMIT 1`.
**Expected:** `assigned_org_id` is non-NULL and `name` is `'Bengaluru Central Corporation'` (or the appropriate corporation for the coordinate).
**Why human:** `get_org_for_ward` uses a live PostGIS DB with seeded ward boundaries and organizations. The SQL is correct but runtime matching requires a live DB.

#### 3. Audit Trail Row Written (NF-03-B SC#3)

**Test:** After submitting the report in test #2, run: `SELECT new_status, note, changed_by FROM status_history WHERE report_id = '<new_report_id>' ORDER BY changed_at ASC`.
**Expected:** At least one row with `new_status = 'open'`, `note = 'Auto-assigned based on ward geography'`, `changed_by IS NULL`.
**Why human:** Best-effort DB insert; requires a live DB to confirm the row was written.

#### 4. CORP Column Shows Full Org Name (NF-03-B SC#2)

**Test:** In the admin reports list desktop table, find a report whose ward is in the Central corporation zone. Verify the CORP column shows `'Bengaluru Central Corporation'` (not `'CENTRAL'` or `'Central'`).
**Expected:** The full org name from the organizations table appears, sourced via `assigned_org_id` JOIN rather than `wards.corporation`.
**Why human:** Requires live DB with both seeded ward boundaries and seeded organization names; visual rendering in the admin UI.
