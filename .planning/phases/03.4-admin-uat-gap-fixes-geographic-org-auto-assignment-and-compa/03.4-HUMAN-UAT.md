### 1. Mobile compact-row full-card tap navigates to detail page
expected: On a mobile viewport (or Chrome DevTools mobile simulation), open the admin reports list and switch to ROWS (compact) view. Tap anywhere on a report card body (NOT the Status or Delete button). The browser navigates to /admin/reports/:id for that report. Tapping Status opens the status control without navigating. Tapping Delete deletes without navigating.
result: [pending]

### 2. New report auto-assigned to BBMP corporation on creation
expected: Submit a new report via the public form at a coordinate that falls within a known BBMP ward (e.g. any point in Bengaluru). After submission, query the database: SELECT r.id, r.assigned_org_id, o.name FROM reports r LEFT JOIN organizations o ON o.id = r.assigned_org_id ORDER BY r.created_at DESC LIMIT 1. The assigned_org_id should be non-NULL and o.name should be one of the 5 BBMP corporations (Bengaluru Central/North/East/South/West Corporation). If the ward falls outside known corporation boundaries the field may be NULL — that is expected.
result: [pending]

### 3. Auto-assignment audit trail row in status_history
expected: For the report created in Test 2 (or any report created after this deployment), query: SELECT * FROM status_history WHERE report_id = '<id>' ORDER BY created_at. There should be a row with new_status = 'open', note = 'Auto-assigned based on ward geography', and changed_by IS NULL. This row confirms the system-action audit trail was written.
result: [pending]

### 4. Admin CORP column shows full org name, not ward geography string
expected: Open the admin reports list (desktop table view). For a report that was auto-assigned (assigned_org_id non-NULL from Test 2), the CORP column should display the full organization name e.g. "Bengaluru Central Corporation" — NOT the short ward geography string "Central". For unassigned reports the column should be empty/dash.
