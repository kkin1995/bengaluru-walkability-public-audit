## Spacing Scale

Standard 8-point grid. Source: `tokens.css` `--grid: 8px`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, dot separators, inline chip padding (vertical) |
| sm | 8px | Card internal row gaps, filter chip gaps, between-label gaps |
| md | 16px | Card padding, sidebar section gaps, form field gaps |
| lg | 24px | Page content padding (desktop), section breaks |
| xl | 32px | Between major dashboard panels |
| 2xl | 48px | Not used in admin (dense tool layout) |
| 3xl | 64px | Not used in admin |

**Exceptions:**
- Bottom tab bar (mobile): 14px bottom padding + 8px top = total 22px safe area padding — accounts for iOS home indicator
- Sidebar width (desktop): 220px fixed — not an 8-point multiple; set by design prototype
- Touch targets: all buttons ≥ 44px min-height (accessibility override) — applies even to xs/sm button sizes when they are the only interactive element in a row
- Top bar (mobile): 12px top / 10px bottom / 14px horizontal — slight asymmetry preserved from prototype for optical balance at 390px viewport; prototype-measured at 390px viewport: 8px caused optical top-heaviness in testing

## Typography

Four roles, three fonts. Source: `tokens.css` and `docs/ADMIN-PORTAL-DESIGN.md`.

Exactly 4 declared sizes. Exactly 2 declared weights.

| Role | Font | Size | Weight | Line Height | Usage |
|------|------|------|--------|-------------|-------|
| Body | Inter | 14px | 400 | 1.5 | Report descriptions, help copy, form field values, card meta, badge text, button text (all sizes), table body, Kannada citizen content, sidebar nav label (passive), filter chip label, compact row meta, login sub-headline |
| Section header | JetBrains Mono | 10px | 600 | 1 | Section labels (uppercase, +0.10em tracking), top bar brand label, footer build hash, security hint, tab bar labels, table column headers, micro meta lines, card/row meta, card category title (weight 600), pagination labels |
| Display / hero | JetBrains Mono | `--text-hero-mobile: 56px` / `--text-hero-desktop: 84px` | 600 | 0.95 | Hero count on dashboard (`218`), report ID in header — responsive breakpoint token, counts as one display role |
| Login headline | JetBrains Mono | 14px | 600 | 1.2 | `$ login` headline and all login screen chrome — uses body size at semibold weight for compact terminal aesthetic |

**Letter spacing:** JetBrains Mono section labels use `+0.10em`; filter chips and nav labels use `+0.04em`; body mono (IDs, timestamps inline in cards) uses `-0.01em` (tighter). Inter body: default (0).

**Size consolidation rationale:**
- Former 11px, 12px, 13px sizes → 10px (section header role) or 14px (body role). The 4px difference at these small sizes is imperceptible at reading distance and creates unnecessary font-size proliferation.
- Former 24px, 26px sizes → retired. Metric card counts and login headline use the 14px body role at weight 600; the hero display role (56px/84px) covers large numerics. No intermediate display size is needed.
- Former weight 500 → reassigned to 400 (passive/body contexts) or 600 (active/emphasis contexts).
- Former weight 700 → reassigned to 600. At 56–84px, weight 600 reads as visually bold without requiring a separate weight token.

| Floating | `box-shadow: 0 8px 24px rgba(10,10,10,0.08), 0 0 0 1px rgba(10,10,10,0.04)` | `--shadow-lg` — modal overlays, map cluster popup |

## Interaction Patterns

### Press / Hover State

Class `.press` on interactive cards and rows:
```css
transition: transform 0.12s ease, background 0.12s ease, border-color 0.12s ease, box-shadow 0.12s ease;
/* :active */ transform: scale(0.985);
```

### Filter Chips

- Horizontal scroll container with `no-scrollbar` class (scrollbar hidden)
- Active chip: ink background, bg text — toggle on click
- Multiple chips can be active simultaneously (category + severity combinations)

### Duplicate Expand Row (Desktop Table)

- Toggle row appears below the linked report row, `warn-bg` background, `colSpan` full width
- Shows: DUP_GROUP label + linked count + confidence + radius + auto-link timestamp
- Inner table of linked reports (no photo thumbnails, just ID / category / ward / time / distance / status / severity)
- Expand/collapse via "COLLAPSE" button in row header

### Status Transitions

- Detail page shows "NEXT_STEP" prompt block in accent-bg: current status → next status, with "Move" button
- On mobile: two-button grid ("Move to review" + "Mark resolved" or "Resolve")
- Status changes trigger `aria-live="polite"` update on the status display region

### Dark Mode Toggle

Toggle via button in sidebar footer or profile page. Sets/removes `.dark` class on `<html>`. Persists to `localStorage`.

### Keyboard Navigation (desktop)

- `⌘K` / `Ctrl+K` global command palette (shown in sidebar hint)
- Sidebar items focusable, `role="navigation"` on sidebar
- Table rows: `role="row"`, report detail navigable with keyboard

## Accessibility Requirements

Source: `docs/ADMIN-PORTAL-DESIGN.md` accessibility overrides + `chats/chat2.md`.

1. **Severity — triple encoding:** Bar pattern (1/2/3 lit) + label text + color. Never color alone. Tested colorblind + grayscale.
2. **All buttons ≥ 44px tap target.** Override where needed: `min-height: 44px` on `md` buttons used as primary actions.
3. **Status regions:** `role="status" aria-live="polite"` on sync indicator, pending-changes card, and any field that updates dynamically without a page navigation.
4. **Icon-only buttons:** Must have `aria-label` (e.g., zoom button, sort button, dots menu).
5. **Offline pending list:** `role="list"` on queued-actions list.
6. **Severity distribution list:** `role="list" aria-label="Open reports by severity"` on the severity composition rows.
7. **Photo:** If a real photo — include `alt="Citizen-submitted photo of {category} at {ward}"`. Photo tile placeholder div: `aria-hidden="true"`.
8. **Table markup:** Use `<table>`, `<thead>`, `<th scope="col">` for reports and users tables — not div grids.

| Duplicate "needs attention" note | "likely duplicate" (sentence case, warn-ink) |
| Admin report ID format | `WLK-{hex5}` — e.g. `WLK-7AC30` (uppercase, mono) |

**Destructive actions in this phase:**
- Delete report — inline danger-soft button in detail top bar; confirmation modal with plain copy above
- Deactivate user — dots menu on user row; confirmation inline or modal

**Confirmation approach:** Inline modal (not browser `confirm()`). Single confirm button (danger) + "Cancel" (ghost). No secondary destructive option.

## Token Implementation Strategy

The current `globals.css` defines `:root` tokens scoped to the citizen-facing Direction A palette. The admin portal uses Direction B tokens. Implementation approach:

1. Add `.admin-portal` class to the admin layout wrapper `<div>` (or to `<body>` via `useEffect` on mount in the admin layout).
2. In `globals.css` (or a new `admin.css` imported only in `app/admin/layout.tsx`), declare `.admin-portal { --bg: #f3f3f1; ... }` overrides for all Direction B tokens.
3. Dark mode: `.dark .admin-portal { ... }` or `.admin-portal.dark { ... }` for dark overrides.
4. Do NOT change `:root` — the citizen-facing pages must continue using their warm green tokens.
5. Font variables (`--font-sans`, `--font-mono`, `--font-kn`) are already correct from Phase 02.3.1 (`next/font/google` injects them as CSS variables). The `--font-display` override (JetBrains Mono as display font in Direction B) is applied by setting `font-family: var(--font-mono)` on admin-specific elements rather than changing the CSS variable.
