# Phase 02.5 Plan 01: Token Foundation and Primitive Library Summary

Direction B "Walkability Console" token layer + 15 admin primitives built with TDD (Wave 0 RED stubs → GREEN implementation), all scoped under `.admin-portal` with CSS custom properties and data-* testability contracts.

## What Was Built

### Token Foundation
- `frontend/app/admin/admin.css` — Direction B tokens transcribed from `design-ref/admin-portal/tokens.css`. Light palette under `.admin-portal { }`, dark palette under `.dark .admin-portal { }`. No `:root` mutations. Includes radii overrides (`--r-xs:4px` through `--r-xl:14px`), shadow overrides (rgba(10,10,10,...)), hero text tokens (`--text-hero-mobile:56px`, `--text-hero-desktop:84px`), `.press` animation utility, `.no-scrollbar` utility.
- `frontend/app/layout.tsx` — JetBrains Mono weight `"600"` added to font load (was `["400","500"]`). `suppressHydrationWarning` added to `<html>` element.
- `frontend/app/admin/layout.tsx` — Imports `admin.css`, wraps content in `<div className="admin-portal">`, injects FOTWT blocking `<script dangerouslySetInnerHTML>` as first Fragment child.

### Hook
- `frontend/app/admin/lib/useOnlineStatus.ts` — Named export `useOnlineStatus(): boolean`. Initializes from `navigator.onLine`, updates on `window` `'online'`/`'offline'` events. 3 tests pass.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed StatusBadge unknown-status aria-label**
- **Found during:** Task 2 — first test run showed 1 failure in StatusBadge.test.tsx
- **Issue:** The fallback for unknown status reused `STATUS_MAP.submitted`'s fixed `ariaLabel: "Status: submitted"`. The test expected the aria-label to contain the raw unknown value ("archived").
- **Fix:** For unknown statuses, construct a dynamic object spreading `STATUS_MAP.submitted` but overriding `ariaLabel` to `"Status: ${status}"` and `label` to the raw status string.
- **Files modified:** `frontend/app/admin/components/StatusBadge.tsx`
- **Commit:** e2f5b31 (included in Task 2 commit)
