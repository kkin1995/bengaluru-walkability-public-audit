## Token File Structure

| Option | Description | Selected |
|--------|-------------|----------|
| New `frontend/app/admin/admin.css` | Separate file imported in admin/layout.tsx — complete isolation from citizen palette | ✓ |
| In `globals.css` inside `.admin-portal {}` | Everything in one file — simpler import graph but harder to review | |

**User's choice:** Separate `admin.css` file.

| Option | Description | Selected |
|--------|-------------|----------|
| `.admin-portal` class on layout `<div>` | Per UI-SPEC language — layout div wraps all admin pages | ✓ |
| `data-theme="admin"` attribute on `<body>` | More semantic; requires client-side `useEffect` to set on body | |

**User's choice:** `.admin-portal` class on layout wrapper div.

| Option | Description | Selected |
|--------|-------------|----------|
| `.dir-b` + `.dir-b.dark` verbatim, plus hero text size tokens | Full copy from design-ref; add `--text-hero-mobile/desktop` per UI-SPEC | ✓ |

**User's choice:** Verbatim copy plus hero tokens. Claude adds `--text-hero-mobile: 56px` and `--text-hero-desktop: 84px` from the UI-SPEC.

| Option | Description | Selected |
|--------|-------------|----------|
| Override radii in admin.css (sharp Direction B scale) | 4/6/8/10/14px — matches prototype chips and cards | ✓ |
| Reuse citizen radii | Simpler but visually wrong (too-rounded for Direction B) | |

**User's choice:** Override radii with Direction B scale.

| Option | Description | Selected |
|--------|-------------|----------|
| Override shadow tokens (cooler rgba(10,10,10,...)) | Fully self-contained scope — industry best practice | ✓ |
| Inherit warm citizen shadows from globals.css | Simpler but shadows look off on teal palette | |

**User's choice:** Override shadows too. User asked for industry best practice recommendation; Claude recommended full scope isolation (all differing tokens overridden), which user accepted.

## Dark Mode FOTWT Prevention

| Option | Description | Selected |
|--------|-------------|----------|
| Blocking inline `<script>` in admin layout | Reads localStorage synchronously before React hydrates; next-themes standard pattern | ✓ |
| CSS `prefers-color-scheme` fallback, JS syncs on mount | Slight flash when user preference differs from OS; no dangerouslySetInnerHTML | |
| Server-side cookie in Server Component | Zero flash; requires cookie write on every toggle + CORS handling | |

**User's choice:** Blocking inline script with `dangerouslySetInnerHTML` + `suppressHydrationWarning`.

| Option | Description | Selected |
|--------|-------------|----------|
| `'admin-theme'` key, default: light | Admin-scoped key; light default for office environment users | ✓ |
| `'theme'` key, default: system | Shared key (collision risk); system default complicates FOTWT script | |

**User's choice:** `admin-theme` key, light default.

| Option | Description | Selected |
|--------|-------------|----------|
| Both sidebar footer (desktop) + profile page | Two toggle locations for convenience; per UI-SPEC | ✓ |
| Profile page only | Simpler; but friction during long triage sessions | |

**User's choice:** Both locations.

## Offline Behavior Scope

| Option | Description | Selected |
|--------|-------------|----------|
| UI states only — show copy when API calls fail | No Service Worker/IndexedDB; navigator.onLine + window events | (partial) |
| Real PWA offline with Service Worker + action queuing | Background Sync, IndexedDB, reconciliation — significant scope | deferred |

**User's choice:** Real offline queuing is deferred to the next feature phase. Phase 02.5 implements UI states only. User explicitly requested this be added to REQUIREMENTS.md and the next phase plan.

| Option | Description | Selected |
|--------|-------------|----------|
| `navigator.onLine` + window `offline`/`online` events | Proactive detection; `useOnlineStatus()` hook | ✓ |
| API call failure only | Reactive; shows stale content until user triggers a load | |

**User's choice:** `navigator.onLine` + event listeners via shared hook.

| Option | Description | Selected |
|--------|-------------|----------|
| Pending card hidden when `pendingCount === 0` | Conditionally rendered; correct behavior for Phase 02.5 | ✓ |
| Pending card always visible as design stub | Misleading to GBA users — shows 'Saved on device' with no items | |

**User's choice:** Pending card only shown when `pendingCount > 0`.
