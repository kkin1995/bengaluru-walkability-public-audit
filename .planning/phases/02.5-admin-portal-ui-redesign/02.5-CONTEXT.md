# Phase 02.5: Admin Portal UI Redesign - Context

**Gathered:** 2026-05-22
**Status:** Ready for planning

<domain>
## Phase Boundary

Implement the hybrid "Walkability Console × Daari Ops" design system for all admin portal screens at `/admin` — CSS variable token layer (`frontend/app/admin/admin.css`), JetBrains Mono chrome, Direction-B teal palette, Direction-A card structure (photo tile + status badge + meta line), light + dark mode with zero flash-of-wrong-theme, and a full accessibility pass — as a pixel-faithful translation of the design prototype in `design-ref/admin-portal/`.

Scope covers:
1. **Token foundation** — `admin.css` with fully scoped Direction-B palette, typography, radii, and shadow overrides
2. **Admin component primitives** — 14 custom components from scratch (Btn, Pill, StatusBadge, SeverityIndicator, Card, SectionLabel, Icon, Input, Select, Avatar, ConfidencePill, PhotoTile, MapPin, Sparkbars), replacing existing Tailwind + lucide-react implementations
3. **All admin screens** — Login, Dashboard (mobile + desktop), Reports list (card stream + compact rows), Report detail, Map view, Users management, Organizations, Profile, Empty/Error/Offline states
4. **Dark mode** — Blocking inline script in admin layout for FOTWT-free toggle, persisted to `localStorage` under `admin-theme` key

Real PWA offline (Service Worker + IndexedDB action queuing) is **explicitly deferred** — see Deferred section.

</domain>

<decisions>
## Implementation Decisions

### Token File Structure
- **D-01:** Admin tokens live in a new `frontend/app/admin/admin.css` file, imported only in `app/admin/layout.tsx`. Completely isolated from the citizen-facing `globals.css` — no risk of token bleed between Direction A (citizen) and Direction B (admin).
- **D-02:** Tokens are scoped under `.admin-portal { }` class applied to the outermost layout `<div>` wrapper (not to `<body>`). Dark overrides: `.dark .admin-portal { }`.
- **D-03:** `admin.css` transcribes the full `.dir-b` and `.dir-b.dark` blocks verbatim from `design-ref/admin-portal/tokens.css`, covering palette, shadows, and radii. Hero text size tokens (`--text-hero-mobile: 56px`, `--text-hero-desktop: 84px`) are added per UI-SPEC since they are not in `globals.css`.
- **D-04:** Radii are overridden in `admin.css` — Direction B uses a sharper scale (`--r-xs: 4px`, `--r-sm: 6px`, `--r-md: 8px`, `--r-lg: 10px`, `--r-xl: 14px`, `--r-full: 999px`) vs. the citizen-facing rounder scale. All six radius tokens must be declared in the `.admin-portal` scope block.
- **D-05:** Shadow tokens are overridden in `admin.css` — Direction B uses cooler neutral shadows (`rgba(10,10,10,...)`) to match the teal palette, vs. the warm stone shadows in `globals.css`. The `.admin-portal` scope is fully self-contained; it does not inherit citizen-facing token values.

### Existing Component Migration
- **D-06:** Existing admin components (`AdminSidebar.tsx`, `ReportsTable.tsx`, `StatusBadge.tsx`, `StatsCards.tsx`, `UserManagementTable.tsx`, `CreateUserModal.tsx`) are **rewritten in-place, file by file**. No parallel v2/ directory. Tests are updated alongside each component rewrite.
- **D-07:** `lucide-react` icon usage is replaced with the custom `Icon` component from `design-ref/admin-portal/primitives.jsx`. The Icon component uses 50+ named inline SVG paths (24×24 viewBox, Lucide-compatible paths). This removes the npm dependency and ensures icon style matches the design prototype exactly.
- **D-08:** New admin primitive components (Btn, Pill, StatusBadge, SeverityIndicator, Card, SectionLabel, Avatar, ConfidencePill, PhotoTile, MapPin, Sparkbars, Input, Select, Icon, Kbd) live in `frontend/app/admin/components/` alongside existing components. The executor uses `design-ref/admin-portal/primitives.jsx` as the prop API specification for each component.
- **D-09:** Styling uses CSS custom properties via inline `style` objects exclusively — **no Tailwind** in rewritten components. This is consistent with the project's established pattern for all new/redesigned code (Phase 02.3.1 precedent).

### Dark Mode
- **D-10:** FOTWT prevention via a **blocking inline `<script>` in `app/admin/layout.tsx`** added to the `<head>`. The script reads `localStorage.getItem('admin-theme')` before React hydrates and synchronously adds `.dark` to `<html>` if needed. Add `suppressHydrationWarning` to the `<html>` element to silence the expected server/client class mismatch.
  ```
  // Pattern:
  (function() {
    var dark = localStorage.getItem('admin-theme') === 'dark';
    if (dark) document.documentElement.classList.add('dark');
  })();
  ```
- **D-11:** `localStorage` key is `'admin-theme'`, scoped to avoid collision with any future citizen-facing theme toggle. Default (no key set) = **light mode**. Rationale: GBA government workers are most likely in lit office environments.
- **D-12:** Dark mode toggle appears in **both** the sidebar footer (desktop, for quick in-session switching) and the profile page (canonical settings location). Reads and writes `localStorage` on the client side; uses `window.__setTheme()` or direct `classList` toggle.

### Offline Behavior (Phase 02.5 scope only)
- **D-13:** Phase 02.5 implements **UI states only** — no Service Worker, no IndexedDB, no action queuing. When `navigator.onLine === false` or the `'offline'` window event fires, the admin pages show the offline state UI using the copywriting contract from the UI-SPEC. When the `'online'` event fires, normal operation resumes.
- **D-14:** The `'Saved on this device'` pending changes card renders conditionally: `{pendingCount > 0 && <PendingCard />}`. Since there is no action queuing in Phase 02.5, `pendingCount` is always 0 and the card never shows. When real queuing is implemented in a future phase, it will appear automatically.
- **D-15:** Offline detection hook pattern: check `navigator.onLine` on mount + listen to `window.addEventListener('offline', ...)` and `window.addEventListener('online', ...)`. A shared `useOnlineStatus()` hook is created and used across admin pages that show offline states.

<specifics>
## Specific Ideas

- The blocking FOTWT script uses `dangerouslySetInnerHTML` in a `<script>` tag placed in `<head>` via the admin layout. The outer `<html>` element needs `suppressHydrationWarning` to prevent React's hydration error when the class is set before React mounts.
- Direction B shadow spec: `--shadow-sm: 0 0 0 1px rgba(10,10,10,0.04)` / `--shadow-md: 0 1px 2px rgba(10,10,10,0.04), 0 0 0 1px rgba(10,10,10,0.04)` / `--shadow-lg: 0 8px 24px rgba(10,10,10,0.08), 0 0 0 1px rgba(10,10,10,0.04)` — cooler and flatter than citizen-facing shadows.
- SeverityIndicator bar spec: 3 bars of heights `[4px, 8px, 12px]`, width `3px`, gap `2px`, lit bars use `sev-{level}` color, unlit bars use `--border-strong`. Always accompanied by text label for WCAG 1.4.1 compliance.
- `useOnlineStatus()` hook reads `navigator.onLine` on mount and subscribes to `'offline'`/`'online'` window events. All data-fetching admin pages use this hook to conditionally render the offline state UI from the copywriting contract.
- Pending changes card: `{pendingCount > 0 && <PendingCard />}` — always hidden in Phase 02.5 since `pendingCount` is always 0 with no queuing. This is the correct implementation; it becomes visible automatically when real offline queuing is added.

</specifics>
