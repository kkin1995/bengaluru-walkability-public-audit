# Phase 02.5: Staging UAT Session — 2026-05-24

**Environment:** https://staging.nammadaari.com/admin
**Device:** iPhone, iOS Safari, mobile viewport
**Tester:** kkin1995
**Screenshots:** 9 screenshots covering all tested screens (see frontmatter)

## Context

This is a full admin portal staging UAT covering all 5 accessible screens:
OPS (dashboard), Queue, Map, Users, and New User modal. The previous UAT
session (02.5-UAT.md, 2026-05-23) ran on a local build; this session is the
first full pass on staging.nammadaari.com over HTTPS on a real iOS device.

---

## Findings

### STG-01 — No logout button or profile access on mobile (confirmed-bug)

**Screen:** OPS (dashboard) and all other admin pages
**User report:** "No sidebar / logout button on home page"
**Screenshot:** IMG_4731.jpg, signal-2026-05-24-134038.png

The admin portal on mobile shows only the bottom tab bar (OPS / QUEUE / MAP / USERS).
There is no hamburger menu, no sidebar, and no path to reach the Profile page or the
Logout action from any mobile screen. Admins logged in on a mobile device have no way
to log out. Profile, Organizations, and the dark-mode sidebar toggle in the sidebar
footer are all unreachable via the mobile navigation.

**Related prior bug:** BUG-T6-02 (Log out all sessions hidden behind mobile nav).
That bug was logged as "fixed in e07368a" but this staging session confirms the
root problem — mobile navigation has no path to logout at all, not just scrolling.

**Classification:** confirmed-bug
**Severity:** HIGH — security issue; admins cannot log out on mobile
**Fix area:** `AdminSidebar.tsx` — mobile tab bar needs a profile/logout tab or
a hamburger icon that expands to show sidebar links including Logout.

---

### STG-02 — Recent Activity shows stub/template data, not backend data (confirmed-bug)

**Screen:** OPS (dashboard) — "RECENT ACTIVITY" section
**User report:** "Template content under 'Recent Activity' needs to be pulled in from backend"
**Screenshot:** IMG_4731.jpg, signal-2026-05-24-134038.png

The Recent Activity feed on the dashboard shows hardcoded stub entries:
- 09:42 "New" Damaged Footpath
- 09:11 "Under review" No Footpath
- 08:55 "New" Unsafe Crossing

The live data shows: Total Reports = 1, Under Review = 0. The stub feed shows
an "Under review" entry — confirming these are not real API data. This was
documented as intentional (`STUB_ACTIVITY`, plan decision D-13, logged as IN-03
in REVIEW.md) but is now flagged as unacceptable for staging use.

**Classification:** confirmed-bug (intentional stub — now rejected by tester)
**Severity:** MEDIUM — admin dashboard shows false activity to operators
**Fix area:** `frontend/app/admin/page.tsx` — `STUB_ACTIVITY` constant (line 20–28)
must be replaced with a real API call to the backend (e.g. a new endpoint
`GET /api/admin/activity` or reusing `GET /api/admin/reports?limit=5&sort=updated_at`).

### STG-03 — Report photos not showing in Queue (regression) (confirmed-bug)

**Screen:** Queue — CARDS view
**User report:** "Photo of each report not showing in Queue, it was showing when I hosted locally"
**Screenshot:** signal-2026-05-24-134038-1.png

Report cards in the Queue show a gradient/icon placeholder instead of the actual photo
thumbnail. The same photo DID render when running locally. This is a staging-specific
regression of BUG-T3-01 from the previous UAT session.

BUG-T3-01 was logged as "fixed in fix commit e07368a — image_path fallback added" in
VERIFICATION.md, but the fix is not working on staging. Root cause is likely an image
URL construction issue: local dev served images from `localhost:3001/uploads/` but staging
serves from a different path or origin. The `image_path` → `image_url` construction may
not account for the staging base URL.

**Classification:** confirmed-bug (regression of BUG-T3-01)
**Severity:** HIGH — core report review feature broken on staging; admin cannot see photos
**Fix area:** `frontend/app/admin/components/ReportsTable.tsx` line 286 — `PhotoTile` src
construction. Verify that `image_url` or the constructed URL uses the correct base path
for staging (likely `/uploads/<filename>` relative, or a full URL from the API response).

### STG-04 — Queue ROWS view overflows horizontally on mobile (confirmed-bug)

**Screen:** Queue — ROWS view
**User report:** "Report row in Queue page overflows UI on right side"
**Screenshot:** signal-2026-05-24-134038-3.png

In the ROWS view of the Queue page, the report row content (ward + status badge +
"Delete" button) overflows past the right edge of the viewport. The "Status" column
label and "Delete" button are partially cut off. The row requires horizontal scrolling
that is not intended by the design.

**Classification:** confirmed-bug
**Severity:** MEDIUM — ROWS view unusable on mobile; content inaccessible without scrolling
**Fix area:** `frontend/app/admin/components/ReportsTable.tsx` — ROWS view row layout.
Likely needs `overflow: hidden`, `min-width` constraints removed, or a different
responsive layout strategy for mobile (e.g. stack columns or abbreviate labels).

### STG-05 — Admin Map page missing bottom navigation bar (confirmed-bug)

**Screen:** Map (/admin/reports/map)
**User report:** "'Map' page does not show bottom menu bar, therefore cannot navigate"
**Screenshot:** IMG_4735.jpg

The admin Map page renders without the bottom tab bar (OPS / QUEUE / MAP / USERS).
Once a user navigates to the Map page on mobile, there is no way to navigate to any
other admin page. The page is effectively a navigation dead-end on mobile.

Note: IMG_4735.jpg may be the public-facing `/map` page rather than `/admin/reports/map`
— the URL bar shows `staging.nammadaari.com` without a path. If this is the public map,
the admin map page at `/admin/reports/map` should still be verified separately.

**Classification:** confirmed-bug
**Severity:** HIGH — navigation dead-end on mobile; back button is the only exit
**Fix area:** `frontend/app/admin/reports/map/page.tsx` — verify `AdminSidebar` is
included in the layout. If `AdminSidebar` is present in the admin layout and the map
page is within the `/admin` route group, this may be a Leaflet full-screen CSS issue
overriding the tab bar z-index or height.

### STG-06 — Users page table overflows horizontally on mobile (confirmed-bug)

**Screen:** Users (/admin/users)
**User report:** "On 'Users' page, the UI is overflowing on right side"
**Screenshots:** signal-2026-05-24-134038-4.png (left: USER + ROLE columns),
               signal-2026-05-24-134038-5.png (right: STATUS + LAST LOGIN + ACTIONS)

The Users table has more columns than can fit in a mobile viewport. Screenshots show
the table requires horizontal scrolling to see all columns (USER, ROLE, STATUS, LAST
LOGIN, ACTIONS). The ROLE column badge ("SUPER" / "ADMIN") is visible but cut off.

**Classification:** confirmed-bug
**Severity:** MEDIUM — Users page requires horizontal scroll on mobile; not designed for
mobile use
**Fix area:** `frontend/app/admin/components/UserManagementTable.tsx` — table layout
needs to collapse columns or stack on mobile. Alternatively, a responsive card layout
should replace the table at narrow viewports.

### STG-07 — Dark mode toggle presence on non-OPS pages (pending-uat)

**Screen:** Queue, Map, Users
**User report:** "No light mode / dark mode toggles on any other page other than home page"

The tester reports the dark mode toggle is absent on pages other than the OPS dashboard.

**Classification:** pending-uat
**Severity:** LOW
**Required action:** Tester to re-verify on staging — specifically confirm whether the
moon/sun icon is present and whether clicking it actually toggles dark mode on the Queue,
Map, and Users pages. Also confirm whether the Map page has any theme control given the
existing navigation bug (STG-05).

### STG-08 — No hamburger icon for sidebar navigation on any mobile page (confirmed-bug)

**Screen:** All admin pages
**User report:** "No hamburger icon for left menu bar on any page"
**Screenshots:** All screenshots — none show a hamburger icon

The admin portal on mobile shows only the bottom tab bar. There is no hamburger icon
on any page to expand a sidebar or access secondary navigation items. This is the same
root issue as STG-01 — the combined impact is:

- Profile page: unreachable on mobile
- Organizations page: unreachable on mobile
- Logout: unreachable on mobile (HIGH security severity — see STG-01)
- Dark mode toggle (sidebar footer): unreachable on mobile without a sidebar

**Classification:** confirmed-bug (root cause of STG-01)
**Severity:** HIGH — Profile, Organizations, and Logout are orphaned on mobile
**Fix area:** `AdminSidebar.tsx` — add either (a) a hamburger icon in the top-left of
mobile pages that slides out the full sidebar, or (b) expand the bottom tab bar to
include a "More" tab that links to Profile, Orgs, and Logout.
