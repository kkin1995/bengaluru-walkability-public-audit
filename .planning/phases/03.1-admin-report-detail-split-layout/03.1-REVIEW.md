## Critical Issues

### CR-01: Delete failure is silent — user receives no error feedback

**File:** `frontend/app/admin/reports/[id]/page.tsx:125-134`

**Issue:** `handleDelete` catches the error from `deleteReport`, resets `isDeleting` to `false`, and does nothing else. The delete modal stays open, the button becomes re-clickable, but no error message is surfaced anywhere. From the user's perspective the operation simply "didn't work" with no explanation.

```typescript
// Current — catch swallows the error silently
async function handleDelete() {
  if (!report) return;
  setIsDeleting(true);
  try {
    await deleteReport(report.id);
    setShowDeleteModal(false);
    router.push("/admin/reports");
  } catch {
    setIsDeleting(false);   // ← only side effect; user sees nothing
  }
}
```

**Fix:** Add a `deleteError` state (or reuse `statusUpdateError`) and render it inside the modal:

```typescript
const [deleteError, setDeleteError] = useState<string | null>(null);

async function handleDelete() {
  if (!report) return;
  setIsDeleting(true);
  setDeleteError(null);
  try {
    await deleteReport(report.id);
    setShowDeleteModal(false);
    router.push("/admin/reports");
  } catch {
    setDeleteError("Failed to delete report. Please try again.");
    setIsDeleting(false);
  }
}

// Inside the delete modal JSX, before the button row:
{deleteError && (
  <p role="alert" style={{ fontSize: 13, color: "var(--danger-ink)", marginBottom: 12 }}>
    {deleteError}
  </p>
)}
```

### WR-01: "Zoom photo" button is non-functional interactive element

**File:** `frontend/app/admin/reports/[id]/page.tsx:243-261`

**Issue:** The zoom button (`aria-label="Zoom photo"`) has no `onClick` handler. It is a fully rendered, accessible, keyboard-focusable `<button>` that does nothing when activated. Keyboard and screen-reader users will encounter it, press Enter/Space, and receive no response. This constitutes a broken interactive element, not merely a placeholder.

**Fix:** Either attach a working handler (e.g., open a lightbox), or if the feature is deferred, replace the `<button>` with a `<div aria-hidden="true">` so it is not exposed to assistive technology:

```tsx
// Option A: wire it up
<button
  aria-label="Zoom photo"
  onClick={() => { /* open lightbox */ }}
  ...
>
  ⌕
</button>

// Option B: remove from a11y tree until implemented
<div aria-hidden="true" style={{ ...buttonStyle }}>⌕</div>
```

### WR-02: "Open in Maps" URL uses unguarded latitude/longitude

**File:** `frontend/app/admin/reports/[id]/page.tsx:407`

**Issue:** The Google Maps `href` is constructed by direct string interpolation without null/undefined guards:

```tsx
href={`https://www.google.com/maps?q=${report.latitude},${report.longitude}`}
```

The same fields are accessed with optional chaining everywhere else in the file (lines 301–302, 403). While `AdminReport.latitude` and `AdminReport.longitude` are typed as `number` (non-nullable), the actual API contract is a JSON response. If the backend ever returns `null` for these fields — which the optional chaining usage elsewhere implicitly acknowledges as a real concern — the generated URL becomes `?q=null,null`, silently pointing to the Equator/Prime Meridian intersection rather than failing visibly.

**Fix:** Conditionally render the link or guard with a fallback:

```tsx
{(report.latitude != null && report.longitude != null) ? (
  <a
    href={`https://www.google.com/maps?q=${report.latitude},${report.longitude}`}
    target="_blank"
    rel="noopener noreferrer"
    ...
  >
    Open in Maps ↗
  </a>
) : (
  <span style={{ fontFamily: "var(--font-mono)", fontSize: 11, color: "var(--muted)" }}>
    No coordinates
  </span>
)}
```

### WR-03: `getMe()` promise guard is test-accommodation logic in production code

**File:** `frontend/app/admin/reports/[id]/page.tsx:78-87`

**Issue:** The code explicitly guards against `getMe()` returning `undefined` or a non-thenable value, with a comment stating this is for "test environments (jest.fn() without mockResolvedValue)". Production code should not be written to accommodate unmocked test stubs. If `getMe()` ever returns `undefined` in production (e.g., due to a future refactor), the role would silently default to `"admin"` for all users, granting elevated privileges by default without any indication something went wrong.

```typescript
// Current — production code shaped around test environment behavior
const promise = getMe();
if (promise && typeof promise.then === "function") {
  promise
    .then((user: { role?: string }) => { ... })
    .catch(() => {/* keep default admin */});
}
```

**Fix:** Call `getMe()` normally. The tests that need this mock already have `jest.mock("@/app/admin/lib/adminApi")` applied — they should set `(adminApiModule.getMe as jest.Mock).mockResolvedValue({ role: "admin" })` in their `beforeEach`. The defensive runtime check should be removed from the component:

```typescript
useEffect(() => {
  getMe()
    .then((user) => {
      setRole(user.role === "reviewer" ? "reviewer" : "admin");
    })
    .catch(() => { /* keep default role */ });
}, []);
```

### WR-04: `GbaHierarchyPanel` nothing-state guard misses `undefined` ward_name

**File:** `frontend/app/admin/components/GbaHierarchyPanel.tsx:73`

**Issue:** The nothing-state condition is:

```typescript
if (!hierarchy || hierarchy.ward_name === null) {
```

`WardHierarchy.ward_name` is typed as `string | null`, so TypeScript permits `null` only. However, if the backend ever returns an object without the `ward_name` key (making it `undefined` at runtime), this guard does NOT fire: `undefined === null` is `false`. Execution continues into `wardDisplay` computation:

```typescript
const wardDisplay = wardNumberValid
  ? `${rawWardNumber} · ${hierarchy.ward_name}`   // → "117 · undefined"
  : hierarchy.ward_name;                           // → undefined
```

When `ward_number` is valid and `ward_name` is `undefined`, the display string becomes the literal `"117 · undefined"` which would render in the DOM.

**Fix:** Use a loose falsy check to cover both `null` and `undefined`:

```typescript
if (!hierarchy || !hierarchy.ward_name) {
```

### WR-05: Test fixture `FULL_REPORT` omits required Phase 3 fields from `AdminReport`

**File:** `frontend/app/admin/reports/[id]/__tests__/page.test.tsx:49-68`

**Issue:** `FULL_REPORT` is missing three required (non-optional) fields added to `AdminReport` in Phase 03:

- `resolution_photo_url: string | null`
- `resolution_notes: string | null`
- `assigned_org_id: string | null`

The fixture is passed as the mock return value of `getAdminReport`. Components mounted during the test (`OrgAssignPanel`, `ResolveModal`) may access `assigned_org_id` at runtime and receive `undefined` instead of `null`. `OrgAssignPanel` specifically reads `report.assigned_org_id` to determine button label ("Assign" vs "Change") — an `undefined` value happens to be falsy so the label defaults to "Assign" without crashing, but this is coincidental correctness, not verified behavior.

**Fix:** Add the missing fields to `FULL_REPORT`:

```typescript
const FULL_REPORT = {
  // ... existing fields ...
  resolution_photo_url: null,
  resolution_notes: null,
  assigned_org_id: null,
};
```

This also closes the TypeScript type gap: if `FULL_REPORT` is annotated as `AdminReport`, the compiler will enforce it at the assignment site.

### IN-02: `status.replace("_", " ")` replaces only the first underscore

**File:** `frontend/app/admin/reports/[id]/page.tsx:467`

**Issue:** `String.prototype.replace` with a plain string only replaces the first occurrence. For the current 6-value Phase 3 status enum (`open`, `acknowledged`, `assigned`, `in_progress`, `resolved`, `closed`) this is harmless since only `in_progress` contains an underscore, and it has only one. If a future status with multiple underscores (e.g., `under_manual_review`) is added to the enum, the display would show `"under manual_review"`.

**Fix:** Use a regex with global flag:

```typescript
{report.status.replace(/_/g, " ")}
```

### IN-03: Test coverage gap — Corporation row title not asserted in happy-path test

**File:** `frontend/app/admin/components/__tests__/GbaHierarchyPanel.test.tsx:80-88`

**Issue:** The test "renders bureaucratic chain label/title pairs" asserts `"Chief Commissioner, GBA"` (GBA row) but does not assert `"Chief Commissioner"` (Corporation row). These are two distinct DOM elements. The ISSUE-03 test correctly uses `/Chief Commissioner$/` to distinguish them. However the happy-path chain test silently omits the Corporation row title, meaning a future change that removes or renames the Corporation title would not be caught by this test.

**Fix:** Add an assertion for the Corporation row title:

```typescript
// In the "renders bureaucratic chain label/title pairs" test:
expect(screen.getByText("Chief Commissioner")).toBeInTheDocument();
```

Note: `screen.getByText("Chief Commissioner")` will uniquely match the Corporation row title because the GBA row title is the distinct string `"Chief Commissioner, GBA"`.
