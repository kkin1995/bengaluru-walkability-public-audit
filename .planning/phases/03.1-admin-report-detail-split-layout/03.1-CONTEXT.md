# Phase 3.1: Admin Report Detail — Split Layout - Context

**Gathered:** 2026-05-26
**Status:** Ready for planning

<domain>
## Phase Boundary

Phase 3.1 delivers two tightly-coupled improvements to `/admin/reports/[id]`:

1. **Layout restructure** — The existing two-column desktop split is rebalanced: left column becomes "report identity" (photo + metadata), right column becomes "action rail" (action panels, GBA hierarchy, history). The right column independently scrolls so all action panels are reachable without scrolling the whole page. This fixes ISSUE-07 (below-fold discoverability).

2. **UAT bug fixes** — All 7 issues from `03-UAT-ISSUES.md` are addressed. ISSUE-07 is resolved by the layout restructure; ISSUE-01..06 are display bugs in GbaHierarchyPanel and the status history timeline.

No new features, no new API endpoints. Frontend-only except for any backend data issues discovered during bug investigation.

</domain>

<decisions>
## Implementation Decisions

### Left Column Content
- **D-01:** Left column = photo hero (flex: 1, fills remaining height) + identity strip anchored below the photo (non-scrolling). Left column does not scroll.
- **D-02:** Identity strip contains: status badge + severity indicator + ConfidencePill + DUP +N pill (duplicate count) + category title + telemetry grid (LAT, LNG, WARD, LOCATION_SRC, SUBMITTED_AT, CATEGORY, DUP_CONF, UUID). Duplicate signals stay in the identity strip — they are read-only severity context, not interactive.
- **D-03:** Left column = `display: flex; flex-direction: column; height: calc(100vh - 120px); overflow: hidden`. Photo section = `flex: 1; min-height: 200px; overflow: hidden`. Identity strip = `flex-shrink: 0`.
- **D-04:** Desktop breakpoint changes from **1024px to 768px** per roadmap success criteria (≥768px triggers split layout). Update `matchMedia("(min-width: 1024px)")` → `matchMedia("(min-width: 768px)")`.

### Right Column Content
- **D-05:** Right column = StatusActionPanel + statusUpdateError + OrgAssignPanel + GbaHierarchyPanel + citizen description card + map thumbnail + status history card. These move OUT of the shared `rightPanel` variable — right column starts with the action panels, not metadata.
- **D-06:** Right column = `overflowY: "auto"`, `maxHeight: "calc(100vh - 120px)"`, `borderLeft: "1px solid var(--border)"`. No change from current right-column scroll implementation.

### UAT Bug Fixes — All In Scope
- **D-07:** ISSUE-01..06 are all fixed in Phase 3.1. Phase 3.1 is the UAT polish phase — no separate micro-phase for these display bugs.
- **D-08:** ISSUE-03 (personnel columns showing placeholder text): **Conditional rendering** in GbaHierarchyPanel. Hide hierarchy rows where the personnel/contact field is null or empty; show when a value is present. Do NOT show "—" or "Not available" for missing contacts — hide the row entirely. This applies to any title column that implies a named contact (e.g., "Ward Supervisor", "Field Contact") where no data exists in the DB.
- **D-09:** ISSUE-07 is addressed by the layout restructure (D-01..D-06) — no separate fix needed.

<specifics>
## Specific Ideas

### Layout Reference — "Figma Inspect Panel / VS Code Sidebar Pattern"
The roadmap explicitly references this pattern. Characteristics:
- Left pane = stable context (in VS Code: the file being edited; here: the report photo + identity)
- Right pane = actionable panels that scroll independently (in VS Code: sidebar with file explorer/git/extensions; here: status actions + GBA hierarchy + history)
- Left pane does NOT scroll — it stays anchored while the right rail scrolls
- On narrow screens (mobile), collapses to single column (already implemented)

### Breakpoint Note
Roadmap success criteria: "On desktop (≥768px)". Current `isDesktop` uses `(min-width: 1024px)`. Change the MediaQuery string only — all conditional rendering logic stays the same.

### Personnel Column Conditional Rendering
The `ChainRowItem` `title` prop shows role labels like "Ward Engineer", "Asst. Revenue Officer". These are static strings — they're always shown regardless of data. ISSUE-03 implies some rows show "Ward Supervisor (? )" placeholder-style text. 

Planner should:
1. Review what the actual `bureaucraticChain` array looked like at UAT time vs. current code
2. For any row where the `title` represents a named contact (not a static organizational role), apply conditional rendering: skip the row when `name` is null
3. For rows like "GBA" with a hardcoded `name: "Greater Bengaluru Authority"`, always show

</specifics>
