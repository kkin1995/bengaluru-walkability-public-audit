## ISSUE-03.1-A: Multiple scrollbars on report detail desktop layout

**Page:** `/admin/reports/[id]`
**Observed:** 2 scrollbars visible simultaneously on desktop view:
1. A scrollbar on the right edge of the identity strip / left column area
2. A scrollbar on the right edge of the right rail column

**Expected:** Exactly 1 scrollbar — the right rail's scrollbar (correct, intentional). No scrollbar on the identity strip section or on the `<main>` element.

**Root cause area:** The identity strip div still shows a scrollbar track (possibly the `overflow: hidden` fix was not reloaded at time of observation). Additionally, the `<main overflowY:auto>` in the admin layout may still show its own scrollbar track when content is slightly taller than 100vh on the user's specific viewport height.

**Fix direction:** Verify `overflow: hidden` on identity strip is active after latest reload. If `<main>` scrollbar persists, adjust the `calc(100vh - 120px)` constant to match actual non-grid height on the target viewport, or use a flex-fill approach for the grid height.

**Category:** confirmed-bug
**Scope:** frontend — `frontend/app/admin/reports/[id]/page.tsx`, `frontend/app/admin/layout.tsx`

## ISSUE-03.1-B: 7D / 14D / 30D intake period buttons not clickable on admin dashboard

**Page:** `/admin` (dashboard / OPS page)
**Observed:** The INTAKE chart shows 7D, 14D, 30D filter buttons. 14D is visually active (selected). Clicking 7D or 30D has no effect — the chart does not update and the active state does not change.

**Expected:** Clicking a period button should update the active state and re-fetch/re-render the intake chart for the selected window.

**Root cause area:** The period buttons are likely rendered as visual elements without wired-up `onClick` handlers, or the handler is present but the chart data is not re-fetched / the state is not updating. This is a pre-existing issue unrelated to Phase 03.1 changes.

**Fix direction:** Locate the dashboard/intake chart component, verify `onClick` on each period button calls `setActivePeriod(period)` (or equivalent), and that the chart query re-runs when the period changes.

**Category:** confirmed-bug
**Scope:** frontend — admin dashboard component (likely `frontend/app/admin/page.tsx` or a dashboard sub-component)
