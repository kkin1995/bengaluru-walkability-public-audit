## ISSUE-03.1-A: Three scrollbars visible on report detail desktop layout

**Page:** `/admin/reports/[id]`
**Observed:** 3 scrollbars visible simultaneously on desktop view:
1. **App scrollbar — right rail** (right of the photo/left column): styled scrollbar, correct and intentional — scrolls the action panels
2. **App scrollbar — identity strip** (below the photo in the left column): same styled look as #1, should not exist — the identity strip should be clipped not scrollable
3. **Browser scrollbar — page/main** (different visual appearance from #1 and #2, native browser scrollbar): indicates `<main>` or the document is still overflowing the viewport

**Expected:** Exactly 1 scrollbar — the right rail (#1). No scrollbar on the identity strip, no browser-native page/main scrollbar.

**Root cause area:**
- Identity strip (#2): The `overflow: hidden` fix committed in 7e14e55 may not have been active at time of observation (pre-reload). Verify on next reload.
- Browser scrollbar (#3): The `<main overflowY:auto>` in the admin layout still overflows slightly. The `calc(100vh - 120px)` grid height estimate is off for this user's viewport — total page content exceeds `<main>` height by a few pixels, causing the native browser scrollbar to appear.

**Fix direction:**
- For #2: confirm `overflow: hidden` on identity strip is live (commit 7e14e55).
- For #3: replace the hardcoded `calc(100vh - 120px)` with a flex-fill approach — make the report-detail div a flex column at `height: 100%`, the action bar takes its natural height, and the grid takes `flex: 1`. This eliminates the magic constant entirely.

**Category:** confirmed-bug
**Scope:** frontend — `frontend/app/admin/reports/[id]/page.tsx`, `frontend/app/admin/layout.tsx`

## ISSUE-03.1-B: 7D / 14D / 30D intake period buttons not clickable on admin dashboard

**Page:** `/admin` (dashboard / OPS page)
**Observed:** The INTAKE chart shows 7D, 14D, 30D filter buttons. 14D is visually active (selected). Clicking 7D or 30D has no effect — the chart does not update and the active state does not change.

**Expected:** Clicking a period button should update the active state and re-fetch/re-render the intake chart for the selected window.

**Root cause area:** The period buttons are likely rendered as visual elements without wired-up `onClick` handlers, or the handler is present but the chart data is not re-fetched / the state is not updating. This is a pre-existing issue unrelated to Phase 03.1 changes.

**Fix direction:** Locate the dashboard/intake chart component, verify `onClick` on each period button calls `setActivePeriod(period)` (or equivalent), and that the chart query re-runs when the period changes.

**Category:** confirmed-bug
**Scope:** frontend — admin dashboard component (likely `frontend/app/admin/page.tsx` or a dashboard sub-component)

## ISSUE-03.1-C: "Close Report" button rendered in its own isolated section in the right rail

**Page:** `/admin/reports/[id]`
**Observed:** The "Close Report" button (from StatusActionPanel) appears at the very top of the right rail in its own padded section, completely alone. The button has excess vertical space around it — it looks like a standalone panel for a single element rather than an action integrated into the flow.

**Expected:** The status action (Close Report / mark action) should be visually grouped or the section spacing should be tighter when only one action is present. The isolated single-button section looks unfinished.

**Root cause area:** `StatusActionPanel` likely wraps its content in a Card/section regardless of how many actions it renders. When only one action button is present (e.g., "Resolved" state shows only "Close Report"), the section padding dominates and the button floats in whitespace.

**Fix direction:** In `StatusActionPanel`, either reduce the section padding when a single action is rendered, or remove the outer Card wrapper and render the action button inline in the right rail without extra section chrome.

**Category:** ux-improvement
**Scope:** frontend — `frontend/app/admin/components/StatusActionPanel.tsx` (or wherever the action panel section wrapper lives)
**Noted:** 2026-05-30 during Phase 03.1 UAT (not in spec — deferred to future phase)
