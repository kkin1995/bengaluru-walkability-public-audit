    In `.github/workflows/ci.yml`, add two new steps to the `backend-checks` job AFTER the existing "Unit tests" step:

    ```yaml
        run: cargo install cargo-audit --locked

      - name: Dependency audit (cargo audit)
        working-directory: backend
        run: cargo audit
    ```

    Note: `cargo audit` automatically reads `audit.toml` from the working directory for the allowlist.

    **C. Add npm audit step to frontend-checks job (per D-18, D-19):**

    In `.github/workflows/ci.yml`, add a new step to the `frontend-checks` job AFTER the existing "Test" step:

    ```yaml
      - name: Dependency audit (npm audit)
        working-directory: frontend
        run: npm audit --audit-level=high
    ```

    npm audit uses the `--audit-level=high` flag per D-18, so only high and critical vulnerabilities fail CI. Low and moderate are informational only.

    Note on D-20 for frontend: npm audit has no native allowlist file format like audit.toml. If a high/critical CVE with no fix blocks CI in the future, the standard approach is `npm audit --audit-level=high || true` with a comment explaining the known CVE, or using `better-npm-audit` as a devDependency. For now, the bare `npm audit --audit-level=high` is sufficient since there are no known unresolvable high CVEs.
