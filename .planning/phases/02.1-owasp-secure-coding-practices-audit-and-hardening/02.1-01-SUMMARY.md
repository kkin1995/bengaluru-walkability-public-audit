**Stripped PII from public API, eliminated duplicate require_role, and replaced all serde_json .unwrap() calls with proper error handling**

## Accomplishments

### Task 1 — Strip submitter_name from public API (SEC-01/A01)

- Removed `pub submitter_name: Option<String>` from `ReportResponse` struct — compile-time guarantee prevents any future reintroduction
- Removed `submitter_name: self.submitter_name` mapping from `Report::into_response()`
- Added `#[allow(dead_code)]` to `Report::submitter_name` (DB field retained for sqlx deserialization)
- Added `test_response_omits_submitter_name` unit test mirroring the existing `test_response_omits_submitter_contact` pattern
- Fixed `fake_success_response()` in `handlers/reports.rs` to match updated struct
- All 15 report model tests pass including new test

### Task 2 — Remove duplicate require_role + fix serde_json unwraps (SEC-02/SEC-03/A01/A10)

- Deleted local `require_role` function from `handlers/admin.rs` (strict-equality only, no admin-is-superset)
- Test module updated to import `require_role` and `JwtClaims` from `crate::middleware::auth` — tests now validate the canonical implementation
- Replaced 4 `serde_json::to_value(..).unwrap()` calls with `.map_err(|e| AppError::Internal(e.to_string()))?`:
  - `admin_me` handler (line 390)
  - `admin_get_stats` handler (line 602)
  - `admin_list_users` handler (line 617 — updated `.map()` to `collect::<Result<Vec<_>, _>>()?`)
  - `admin_create_user` handler (line 656)

## Decisions Made

- **Compile-time PII exclusion**: removing the field from the struct is stronger than runtime filtering — a future developer cannot accidentally re-add the field to a response without a struct change
- **Test module uses middleware JwtClaims**: since require_role now lives exclusively in middleware::auth, tests must use that type to avoid the "similar but distinct types" footgun
- **AppError::Internal for serialization failures**: consistent with the existing error handling pattern; serde_json should never fail on valid structs but returning a 500 is correct if it does
