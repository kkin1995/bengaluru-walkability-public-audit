## Decisions Made

- INTAKE_SQL defined as const (not inline) — single source of truth for both runtime query and test helper; follows STATUS_HISTORY_SQL pattern established in Plan 01
- Runtime query uses `sqlx::query()` (not `query_as!`) — cargo test runs without a live DB
- `($1 || ' days')::INTERVAL` with bound parameter — T-intake-sqli mitigation; verified by cargo check
- `days.clamp(1, 90)` in handler before DB call — T-intake-dos; WHERE clause provides additional bound via the interval
- Zero-fill iterates `i` from `dayCount-1` down to `0` so index 0 = oldest day, index N-1 = most recent — natural left-to-right chronological chart
- On fetch error: all-zero array of correct length — no crash, no phantom stub bars on transient network failure
