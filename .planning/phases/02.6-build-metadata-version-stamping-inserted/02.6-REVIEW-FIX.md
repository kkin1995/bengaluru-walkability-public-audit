### WR-01: Mobile tab-bar hardcodes `repeat(5, 1fr)` grid but conditionally hides one item

**Files modified:** `frontend/app/admin/components/AdminSidebar.tsx`
**Commit:** `454b983`
**Applied fix:** Added `visibleMobileTabs` computed from `MOBILE_TABS.filter(tab => !(tab.roleGated && !isAdminOrSuper))` before the sidebar JSX. Changed `gridTemplateColumns` from the hardcoded `"repeat(5, 1fr)"` to the template literal `` `repeat(${visibleMobileTabs.length}, 1fr)` ``. Changed the map call from `MOBILE_TABS.map(...)` to `visibleMobileTabs.map(...)` (the `if (tab.roleGated && !isAdminOrSuper) return null` guard inside the map was also removed, as filtering is now done before render). Reviewer-role users see a balanced 4-column grid; admins see 5 columns.

### WR-02: `super_admin` role string in `isAdminOrSuper` check is dead code

**Files modified:** `frontend/app/admin/layout.tsx`
**Commit:** `cad4f69`
**Applied fix:** Expanded the `res.json()` type cast from `{ role?: string }` to `{ role?: string; is_super_admin?: boolean }`. Changed the role assignment from `user.role ?? 'reviewer'` to `user.is_super_admin ? 'super_admin' : (user.role ?? 'reviewer')`. This synthesises the `"super_admin"` string that `AdminSidebar.isAdminOrSuper` already checks for, making the existing sidebar guard work correctly for super-admin users without changing the sidebar itself.

### WR-03: Duplicate `<link rel="manifest">` in rendered HTML

**Files modified:** `frontend/app/layout.tsx`
**Commit:** `b6788f2`
**Applied fix:** Removed the explicit `<link rel="manifest" href="/manifest.json" />` from the `<head>` block (line 52). The `manifest` field in the `metadata` export (line 33) causes Next.js to inject this tag automatically; the explicit tag was a duplicate that would have produced two identical manifest links in the rendered HTML.

---

### IN-01: Both nav landmarks share the same `aria-label` while both remain in the accessibility tree

**Files modified:** `frontend/app/admin/components/AdminSidebar.tsx`
**Commit:** `b174ddd`
**Applied fix:** Added `aria-hidden={!isDesktop}` to the desktop `<nav>` element and `aria-hidden={isDesktop}` to the mobile tab bar `<nav>` element. CSS `display:none` does not remove elements from the accessibility tree — screen readers would previously encounter two navigation landmarks with identical labels simultaneously. With this fix, only the currently visible nav is exposed to the accessibility tree at any given time.

---

### IN-02: Wildcard `remotePatterns` in `next/image` config allows proxying images from any host

**Files modified:** `frontend/next.config.mjs`
**Commit:** `833e7a5`
**Applied fix:** Replaced the two wildcard `hostname: "**"` patterns with an explicit allowlist: `localhost` (http, local dev), `backend` (http, Docker internal network), and `staging.nammadaari.com` (https, staging). A codebase audit confirmed no files import `next/image`, so no additional hostnames were needed. The Railway URL suggested in REVIEW.md was intentionally excluded — it is not referenced anywhere in the codebase.
