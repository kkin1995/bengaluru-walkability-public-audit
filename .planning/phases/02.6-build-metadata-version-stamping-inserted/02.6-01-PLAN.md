<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| build-time → runtime | `package.json` version is read at build by Next.js and embedded in the client JS bundle; no runtime mutation possible |
| local dev → no env var | `APP_VERSION` falls back to `"0.0.0"` if `NEXT_PUBLIC_APP_VERSION` is absent (e.g. raw Jest runs) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.6-01 | Information Disclosure | NEXT_PUBLIC_APP_VERSION in client bundle | accept | Version string is intentionally public (printed in footer); no PII or secret material is exposed. Semver in client JS is industry-standard. |
| T-02.6-02 | Tampering | package.json read at build | mitigate | `fs.readFileSync` of a file inside the repo is build-time only; the file is committed to git. Any tampering would require commit access, which is already inside the trust boundary. |
| T-02.6-03 | Tampering | Build-time env injection | mitigate | `next.config.mjs` injects only the `version` field (a string), not the full package.json contents — narrowest possible surface. JSON.parse cannot execute code. |
| T-02.6-04 | Spoofing | Footer brand string `Namma Daari · v{X}` | accept | The brand prefix is static and the version is build-time bound. No user input is interpolated into the footer. |
| T-02.6-SC | Tampering | npm/pip/cargo installs | accept | This plan adds zero new npm packages — `fs`, `url`, `path` are Node built-ins. No package legitimacy audit required. |
</threat_model>
