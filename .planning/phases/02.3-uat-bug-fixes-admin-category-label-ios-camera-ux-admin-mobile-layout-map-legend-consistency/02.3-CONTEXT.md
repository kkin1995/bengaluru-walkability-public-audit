## Phase Boundary

Issues in scope:
- **BUG-01**: Admin reports table shows raw snake_case enum (`broken_footpath`) instead of human-readable label ("Damaged Footpath")
- **BUG-02**: iOS camera UX — two-button pattern (Take Photo / Upload from Gallery) both trigger the same iOS action sheet due to hidden input + `.click()` pattern ignoring `capture` attribute
- **UX-01**: Admin reports table overflows horizontally on mobile portrait with no visual scroll affordance
- **UX-02**: Admin sidebar has no hamburger trigger on mobile — navigation unreachable without undiscoverable gesture

<decisions>
## Implementation Decisions

### BUG-01: Admin Category Label
- **D-01:** Use the existing `getCategoryLabel(value).en` function from `app/lib/translations.ts` in `ReportsTable.tsx`. The function already exists and maps all snake_case enums to human-readable English labels. This is a one-line fix at line 116 (and line 231 for the dedup sub-table row).

### BUG-02: iOS Camera UX
- **D-02:** Replace the current hidden-input + `.click()` pattern with a **label-wrapping approach**. Two `<label>` elements, each wrapping a visible `<input type="file">`:
  - Camera label: `<input type="file" accept="image/*" capture="environment">` — triggers camera directly on iOS when tapped via label (not programmatic `.click()`)
  - Gallery label: `<input type="file" accept="image/*">` (no `capture`) — opens photo library
- **D-03:** The label-wrapping approach is the correct fix because iOS Safari respects `capture="environment"` when triggered by a direct user tap on a label, but ignores it when triggered via programmatic `.click()` on a hidden input.
- **D-04:** Visual design stays the same — two buttons (large green camera button, smaller gallery button). Only the internal mechanism changes. The `handleFile`, EXIF extraction, compression, and `onPhoto` pipeline are unaffected.
- **D-05:** Ref-based clear logic (`cameraRef.current.value = ""`) must be updated to match the new non-hidden input structure.

### UX-01: Admin Table Mobile Overflow
- **D-06:** Add a **fade gradient scroll indicator** to the right edge of the existing `overflow-x-auto` wrapper in `ReportsTable.tsx`. The wrapper is already on line 87 — add `relative` class to it and insert an absolutely-positioned `pointer-events-none` gradient `div` as a visual affordance. Zero impact on existing tests (no class names, data-testids, or ARIA attributes affected).

### UX-02: Admin Sidebar Mobile
- **D-07:** Extract the sidebar into a new **`AdminSidebar.tsx` client component** (`'use client'`). The server `layout.tsx` passes `role` as a prop to `AdminSidebar`. The client component holds a `useState` boolean for open/closed state.
- **D-08:** Add a **hamburger button** (`☰`) in the admin header (mobile-only, `md:hidden`) that toggles the sidebar. On desktop, sidebar renders as normal fixed left nav. On mobile, sidebar slides in as a drawer using `translate-x` transitions.
- **D-09:** Include a **backdrop overlay** (semi-transparent `div`) behind the open mobile drawer that closes it on tap.
- **D-10:** The server `layout.tsx` retains all auth logic (cookie check, `/api/admin/auth/me` call). Only the sidebar JSX is extracted to the client component.

### UX-03: Map Legend Consistency
- **D-11:** Fix the hardcoded legend labels in `map/page.tsx`. Change "Broken" → "Damaged Footpath" (and all other abbreviated labels to match the canonical names in `translations.ts`).
- **D-12:** Consolidate `ReportsMap.tsx`'s independent `CATEGORY_LABELS` map to import from `translations.ts` via `getCategoryLabel()` instead of maintaining its own parallel label definitions. Single source of truth.

### Claude's Discretion
- Hamburger icon choice (☰ vs Menu icon from lucide-react) — use whatever is already imported or the cleanest option
- Exact Tailwind classes for the fade gradient overlay — use standard approach
- Whether to add a close button inside the mobile sidebar drawer in addition to backdrop dismiss — Claude's call based on UX best practice

</decisions>
