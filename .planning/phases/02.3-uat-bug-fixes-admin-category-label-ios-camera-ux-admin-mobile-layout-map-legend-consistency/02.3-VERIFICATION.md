### Human Verification Required

Five items require real-device or real-browser testing. None block automated verification — the code structure is correct in all cases.

#### 1. iOS camera opens directly

**Test:** On an iPhone (Safari), navigate to /report, tap the green "Take Photo" button.
**Expected:** Camera viewfinder opens immediately — no iOS action sheet offering Photo Library / Take Photo / Choose File.
**Why human:** The `capture="environment"` attribute on a label-wrapped input is a browser-native iOS behaviour. jsdom does not apply `capture` attribute semantics.

#### 2. iOS gallery opens photo library

**Test:** On the same screen, tap the white "Upload from Gallery" button.
**Expected:** iOS photo library (Photos app picker) opens — NOT the camera.
**Why human:** Absence of `capture` attribute on the gallery input must be verified by browser behaviour, not DOM structure alone.

#### 3. Hamburger visible and functional on mobile

**Test:** On a mobile viewport (or DevTools at < 768px), navigate to /admin/reports.
**Expected:** Fixed top-left hamburger icon (Menu icon) visible; tapping it slides the sidebar in from the left with a 200ms transition.
**Why human:** `md:hidden` Tailwind class requires actual CSS media query evaluation; jsdom applies no stylesheets.

#### 4. Backdrop dismisses drawer

**Test:** With sidebar open on mobile, tap the semi-transparent backdrop.
**Expected:** Drawer slides back to the left (-translate-x-full) and backdrop disappears.
**Why human:** Requires visual confirmation of transition and state reset in a real browser.

#### 5. Map legend labels match submission form

**Test:** Navigate to /map. Inspect the legend at the top of the map.
**Expected:** Six items: "No Footpath", "Damaged Footpath", "Blocked Footpath", "Unsafe Crossing", "Poor Lighting", "Other Issue" — all matching the Step 3 category selector in the report wizard.
**Why human:** getCategoryLabel() wiring is verified; visual render in real browser closes the loop on UX-03.
