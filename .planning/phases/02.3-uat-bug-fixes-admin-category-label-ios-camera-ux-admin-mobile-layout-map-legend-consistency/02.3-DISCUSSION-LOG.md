## iOS Camera UX (BUG-02)

| Option | Description | Selected |
|--------|-------------|----------|
| Single button, no capture | Remove gallery button and capture attribute. One unified button, iOS native sheet handles camera/gallery choice. Smallest diff. | |
| Label-wrapping input | Replace hidden input + `.click()` pattern with `<label>` wrapping visible inputs. Camera label uses `capture="environment"`, gallery has none. Best chance of true camera vs. gallery distinction on iOS. | ✓ |
| Copy change only | Rename buttons to better describe iOS sheet. No logic change, confusion persists. | |

**User's choice:** Label-wrapping — user explicitly requested keeping two distinct buttons (Take Photo + Upload from Gallery) that do different things. Label-wrapping is the technically correct approach to achieve this on iOS Safari.

**Notes:** The current hidden-input + `.click()` approach is the root cause — iOS ignores `capture` on programmatic triggers. Label-wrapping uses a direct user tap, which iOS respects. ~80% reliable on iOS 14.5+ including iOS 26; Apple can change behavior in future OS versions.
