Close the 3 design pieces that were deferred or removed during Phase 02.3.1's UI redesign:

3. **Per-category counts on chips** — Each chip shows live count (e.g. "Damaged · 38") derived from the reports already fetched by ReportsMap. Zero extra API calls.

<decisions>
## Implementation Decisions

### Branch Strategy
- **D-01:** Create a new branch from `main` with an appropriate name (e.g. `feat/02.3.2-map-filter-chips`). Do NOT commit to `main`. The `ui-redesign` branch has already been merged and deleted.

### Home Page Count (Piece 1)
- **D-02:** This is already done. `frontend/app/page.tsx` is an async server component that calls `fetchReportTotal()` with `next: { revalidate: 60 }`. Verify the implementation exists and confirm no work is needed.

### Map Filter Chip Strip (Piece 2)
- **D-03:** The chip strip is **always visible** just below the top overlay bar (the back + Bengaluru pill + filter button row). It does NOT toggle on/off — chips are permanently visible.
- **D-04:** The chip strip is **horizontally scrollable** with no visible scrollbar (`.no-scrollbar` CSS class already in `globals.css`).
- **D-05:** **7 chips**: "All" (default selected) + 6 category chips in this order: "Damaged", "Blocked", "No path", "Crossing", "Lighting", "Other". These use the **short design labels** from the 02.3.1 design spec (not the full "Damaged Footpath" strings from `translations.ts`).
- **D-06:** **Filtering behavior**: when a category chip is selected, only pins of that category are visible on the map. All other pins are hidden (not faded — completely absent). "All" restores all pins.
- **D-07:** **Active chip state**: active chip uses `background: var(--ink); color: #fafaf9` (same ink-fill pattern as CategoryGrid). Inactive chips use `background: rgba(255,255,255,0.95); border: 1px solid var(--border)`.

### Per-Category Counts (Piece 3)
- **D-08:** Counts are **derived from the fetched reports array** — zero extra API calls. The chip strip is populated by counting the reports that ReportsMap already fetches.
- **D-09:** ReportsMap gets a new optional `onReportsLoaded?: (reports: Report[]) => void` callback prop. When the fetch completes successfully, ReportsMap calls this with the full unfiltered reports array. `map/page.tsx` stores this array in state and computes per-category counts client-side.
- **D-10:** ReportsMap also gets a new optional `categoryFilter?: string` prop. When set to a category enum value (e.g. `"broken_footpath"`), ReportsMap filters its internal display to only render CircleMarkers for that category. When `undefined` or `"all"`, all markers render.

### Claude's Discretion

- Whether chip count format is `"Damaged · 38"` or `"Damaged (38)"` — use the design spec dot format
- Minimum chip width and overflow behavior at very small screen widths
- Whether the Bengaluru pill in the top bar shows a total count — not required by design, Claude's call
- Test strategy for the new ReportsMap props and chip strip interactions

## Existing Code Insights

### Reusable Assets
- `ReportsMap.tsx` — fetches up to 200 reports from `/api/reports?limit=200`, maintains `reports: Report[]` state internally. Adding `onReportsLoaded` callback and `categoryFilter` prop requires minimal changes.
- `.no-scrollbar` CSS class — already in `globals.css`, applies `scrollbar-width: none` + `::-webkit-scrollbar { display: none }`. Use on chip strip container.
- `.press` CSS class — already in `globals.css`, applies tap feedback animation. Use on each chip.
- `var(--ink)`, `var(--border)`, `var(--r-full)` — design tokens already in `globals.css`.
- CategoryGrid chip active state — `background: var(--ink); color: #fafaf9` pattern is established in `frontend/app/components/redesign/CategoryGrid.tsx`.

### Established Patterns
- `map/page.tsx` is already a `"use client"` component (required for `useState`). No boundary change needed.
- `ReportsMap.tsx` uses `useCallback` + `useEffect` for fetching — the fetch callback should also call `onReportsLoaded` when data arrives.
- The 6 category enum values are: `no_footpath`, `broken_footpath`, `blocked_footpath`, `unsafe_crossing`, `poor_lighting`, `other` — sourced from `translations.ts` CATEGORY_LABEL_MAP keys.

### Integration Points
- `map/page.tsx` → `ReportsMap`: add two new optional props (`categoryFilter`, `onReportsLoaded`). Existing `apiUrl` prop is unchanged.
- Chip strip state: `activeFilter: string` in `map/page.tsx` (default `"all"`). Setter passed to chip onClick handlers.
- Count derivation: `const counts = reports.reduce((acc, r) => { acc[r.category] = (acc[r.category] ?? 0) + 1; return acc; }, {} as Record<string, number>)` — computes all 6 category counts in one pass.
