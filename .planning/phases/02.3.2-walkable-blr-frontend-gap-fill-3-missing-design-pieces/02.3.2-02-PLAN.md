**Addition 2 — CHIPS constant and chipLabel helper.**

Add these two constants at module level (outside the `MapPage` function, after the imports block):

```tsx
type ReportLite = { category: string };

const CHIPS = [
  { label: "All",      value: "all" },
  { label: "Damaged",  value: "broken_footpath" },
  { label: "Blocked",  value: "blocked_footpath" },
  { label: "No path",  value: "no_footpath" },
  { label: "Crossing", value: "unsafe_crossing" },
  { label: "Lighting", value: "poor_lighting" },
  { label: "Other",    value: "other" },
] as const;

function chipLabel(
  chip: (typeof CHIPS)[number],
  counts: Record<string, number>,
  total: number
): string {
  if (chip.value === "all") {
    return total > 0 ? `All · ${total}` : "All";
  }
  const n = counts[chip.value];
  return n != null ? `${chip.label} · ${n}` : chip.label;
}
```

Note: `·` is the middle dot character (U+00B7) used as separator in chip labels per the design spec ("Damaged · 38").

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| API response → allReports state | `data.items` from `/api/reports?limit=200` is stored in React state and used to derive counts |
| activeFilter state → CircleMarker render | Client-side filter string controls which DOM markers render |
| chip onClick → setActiveFilter | User gesture triggers state update; no server call |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.3.2-06 | Tampering | Client-side filter chip (map/page.tsx) | accept | Filter is purely a display concern — it hides markers locally. Server returns all reports regardless of client filter state. An attacker manipulating `activeFilter` via devtools only affects their own view. No server-side security boundary crossed. |
| T-02.3.2-07 | Information Disclosure | `onReportsLoaded` callback exposes full reports array to map/page.tsx | accept | The reports array is already fetched and rendered as markers on the public map. `onReportsLoaded` only surfaces the same data to a parent component for count derivation — no new data exposure. All PII fields (submitter_name) were stripped from the public API in Phase 02.1 (SEC-01). |
| T-02.3.2-08 | Denial of Service | Large `data.items` array (limit=200) stored in two state variables | accept | 200 items is a bounded array. Each item is a small JSON object (8 fields). Storage is ~40-80KB — well within browser memory limits. The `limit=200` cap on the API call is the existing constraint. |
| T-02.3.2-09 | Tampering | Category enum values in CHIPS constant vs server enum values | mitigate | CHIPS values (`broken_footpath`, `blocked_footpath`, `no_footpath`, `unsafe_crossing`, `poor_lighting`, `other`) match the Rust enum variants in the backend. The `.filter()` comparison is a string equality check — an unknown category value simply shows no pins, which is safe (no crash). |
</threat_model>
