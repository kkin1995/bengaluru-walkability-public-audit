## TypeScript Decision: Style Approach

Used the **ternary style split** (two complete style objects, one per active/inactive state) rather than the spread approach. This avoids the TypeScript union error that occurs when `border` appears in both a base object and a conditional spread — the two separate objects each define `border` exactly once with no type ambiguity. Both approaches were noted in the plan as acceptable; ternary was chosen first and passed `npm run build` without errors.
