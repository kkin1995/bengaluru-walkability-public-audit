## Spacing Scale

Declared values (all multiples of 4). Source: existing codebase patterns + 8pt grid (`--grid: 8px` in admin.css).

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, status dot spacing, inline badge padding |
| sm | 8px | Chip row gap, filter select gap, photo label gap |
| md | 16px | Section padding, card inner padding, mobile FAB inset |
| lg | 24px | Desktop FAB inset (`bottom: 24, right: 24`), section breaks |
| xl | 32px | Page-level vertical spacing between sections |
| 2xl | 48px | Major layout breaks (unused in this phase) |
| 3xl | 64px | Page-level spacing (unused in this phase) |

**Exceptions:**
- Admin filter trigger height: 32px (per D-01 design spec — `height: 32px`). This is a toolbar affordance, not a touch target.
- Map chip height: 36px (matches existing category chips in `map/page.tsx`; status chips use the same value per D-08).
- Ward toggle button: 52×52px (per D-18 design spec — `--r-lg: 16px` borderRadius).
- Chip row padding: `0 16px` horizontal, `0` vertical (matches existing chip strip in `map/page.tsx`).
- Photo grid gap (TRIAGE-05 desktop): 20px (nearest multiple of 4 to the design spec's 18px; D-25 specified 18px which is not a multiple of 4). Mobile: 16px.
- Before/after label sublabel spacing: 4px (xs token) between label and sublabel.

## Interaction Contracts

### TRIAGE-01 — Admin Filter Selects

| Event | Behavior |
|-------|----------|
| Page mount | Fetch `GET /api/admin/corporations` and `GET /api/admin/wards`; show "Loading…" disabled state on both selects |
| Corp selected | Narrow ward select to that corp's wards; reset ward selection; re-fetch reports with `corporation_id` param |
| Ward selected | Re-fetch reports with `ward_id` param (alongside existing category/status params) |
| Corp cleared ("All corps") | Reset ward select to show all 369 wards; re-fetch without `corporation_id` |
| Ward cleared ("All wards") | Re-fetch without `ward_id` |
| Fetch error (corps or wards) | Show "Unavailable" disabled on affected select; no modal/toast |
| Ward search typed | Client-side filter of ward list; show "Showing N / 369" count in header; "no ward matches '{q}'" when empty |

### TRIAGE-02/03 — Status Chips

| Event | Behavior |
|-------|----------|
| Status chip tapped | Toggle active state (only one active at a time, or "All statuses" resets); re-filter `allReports` in-memory |
| Category + status both active | AND logic — both filters applied simultaneously |
| Zero results | Empty map — no message, no overlay (consistent with existing category chip behavior) |
| "All statuses" tapped | Clear status filter; show all reports (per category filter if any) |

**Status count logic:** Counts are total per status bucket across ALL reports — not cross-filtered by category. Uses `allReports` (full unfiltered list) for count calculation.

**Status mapping (client-side filter):**
- "Open" matches: `status === 'open' || status === 'acknowledged' || status === 'assigned'`
- "In progress" matches: `status === 'in_progress'`
- "Resolved" matches: `status === 'resolved' || status === 'closed'`

### TRIAGE-04 — Ward Overlay Toggle

| Event | Behavior |
|-------|----------|
| Toggle tapped (OFF → ON) | Show "Loading…" state on button (opacity 0.5, disabled); fetch `GET /api/wards/boundaries`; on success: render `<WardBoundaryLayer>`, change button to ON state, show "Ward boundaries · 369 wards" banner |
| Toggle tapped (ON → OFF) | Remove `<WardBoundaryLayer>` from map; hide banner; return button to OFF state |
| Fetch failure | Silent fail — button returns to OFF state, opacity 0.4, disabled. No error message shown. |
| Ward polygon hovered (desktop) | Leaflet tooltip showing ward name |
| Ward polygon tapped (mobile) | Leaflet tooltip/popup showing ward name |
| GeoJSON loaded | GeoJSON cached in component state — re-toggling ON does not re-fetch |

### TRIAGE-05 — Before/After Photos

- No click/tap interaction. Photos are `display: only`, no lightbox.
- `ResolutionBadge` is purely decorative — no pointer events.
- Sub-label date format: `"DD MMM · CITIZEN"` (original) and `"DD MMM · {admin_corp_name}"` (resolution). Use existing `formatDate()` helper for date portion; corp name from `report.ward_hierarchy?.corporation` as fallback if `assigned_org_id` name unavailable.
