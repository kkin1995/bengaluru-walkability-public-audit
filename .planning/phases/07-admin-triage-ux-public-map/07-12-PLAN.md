<objective>
Fix TRIAGE-04b: clicking a ward polygon on /map shows a black focus/selection rectangle.

Root cause (already diagnosed in REVERIFY-UAT.md): the TRIAGE-04 hover fix set `fill: true, fillOpacity: 0` on ward polygons so the filled interior would catch hover events. That made each polygon an interactive, focusable SVG path. On click the browser/Leaflet applies the default focus outline to the `<path class="leaflet-interactive">`, which renders as a black rectangle around the polygon bounds.

Fix approach (defense in depth — apply BOTH):
1. CSS: suppress the focus outline on Leaflet interactive SVG paths (`outline: none`), so no focus artifact can ever paint.
2. Event handler: on polygon click, blur the focused path element so focus state does not persist.

Constraint: the hover tooltip (TRIAGE-04, D-17) MUST keep working — the polygon stays interactive for hover; we only remove the visible focus artifact, not the interactivity.

Purpose: Cosmetic fix that restores a clean hover-only ward overlay with no click selection artifact.
Output: A globals.css rule plus a click handler in WardBoundaryLayer; manual confirmation that clicking a ward shows no rectangle and hover still shows the ward name.
</objective>
