<objective>
Fix MOB-03 (re-fix): the reports-per-week LineChart on /admin/analytics shows grid/axes but NO colored line paths on mobile. Tapping shows a single dot but still no connecting line.

What was already tried and failed (per 07-09-SUMMARY.md and REVERIFY-UAT.md):
- 07-07: wrapper height fix.
- 07-09: changed ResponsiveContainer to `height="100%"` inside a `height: 300` wrapper div, and added `isAnimationActive={false}` to all Lines. This did NOT resolve the missing line paths in Chrome simulated mobile.

Confirmed remaining root cause: `ResponsiveContainer` relies on a ResizeObserver to measure its parent before Recharts computes each Line's SVG path `d` attribute. On simulated/real mobile the container's measured width is 0 (or arrives after first paint), so Recharts renders the chart with zero plotting width — the line `d` is empty, leaving only the static grid/axes and (on interaction) a single dot. `isAnimationActive={false}` cannot fix this because the geometry itself is never computed.

Fix approach (eliminate the measurement race): replace `ResponsiveContainer` with a directly-sized `LineChart`. Measure the wrapper width once with a `useRef` + `ResizeObserver` (or `getBoundingClientRect` on mount with a window-resize listener) into React state, and pass an explicit numeric `width` and fixed numeric `height` to `<LineChart>`. With concrete numbers, Recharts computes the path `d` synchronously on render and the lines paint immediately.

Purpose: Make the analytics trend lines visibly render on first load on mobile, closing MOB-03.
Output: A self-measuring TrendChart that no longer depends on ResponsiveContainer's deferred measurement; a render test; MOB-04 labels preserved.
</objective>
