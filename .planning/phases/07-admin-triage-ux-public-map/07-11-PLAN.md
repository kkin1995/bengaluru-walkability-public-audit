<objective>
Fix TRIAGE-03: the public /map status filter shows the wrong reports. When "In progress" + "Blocked" are both active, an Open-status (acknowledged/assigned) Blocked report still renders, while the chip reads "In progress · 0".

Root cause (confirmed by reading source): two different bucketing rules exist for the same three status chips.
- Chip COUNTS in `frontend/app/map/page.tsx` (`statusCounts`) bucket via `publicStatusLabel`, which maps `open | acknowledged | assigned → "Open"` and `in_progress → "In progress"`.
- The RENDER filter in `frontend/app/components/ReportsMap.tsx` (`reportStatusMatch`) buckets `in_progress` as `acknowledged || assigned || in_progress`, putting `acknowledged`/`assigned` into the in_progress bucket.

So an `acknowledged` report is counted under "Open" but rendered under "In progress" — exactly the reported defect. The two code paths must use ONE shared bucketing function.

Purpose: Make status filtering correct and internally consistent (D-09 AND logic, D-10 total counts, D-11 client-side), eliminating any future drift between count buckets and render buckets.
Output: An exported `publicStatusMatches(status, bucket)` in `translations.ts`, consumed by the ReportsMap render filter; unit tests; no behavior change to category filtering.
</objective>
