<objective>
Fix CORP_ANALYTICS_SQL: append `::float8` after the `ROUND(..., 1)` expression so PostgreSQL emits OID 701 (float8) instead of OID 1700 (NUMERIC). The sqlx 0.7 feature set in Cargo.toml does not include `bigdecimal` or `decimal`, so `r.try_get::<f64, _>("resolution_rate_pct").ok()` silently returns `None` for every corporation with reports — ANALYTICS-03 is non-functional. No Cargo.toml change is needed; the fix is one SQL token.

Also add a `::float8` regression assertion to the `corp_analytics_joins_on_org_id` test so any future removal of the cast fails the test suite before reaching the live database (per NF-04.1-B).

Purpose: Without this cast, the analytics endpoint returns corporation rows with `resolution_rate_pct: null` for all corporations that have at least one report. The migration (plan 01) correctly populates `wards.org_id`, enabling the JOIN — but the type mismatch causes all resolution rates to vanish silently. This one-line fix makes ANALYTICS-03 functional.

Output: Single-token SQL change in admin_queries.rs + one new assertion in analytics_tests.rs.
</objective>
