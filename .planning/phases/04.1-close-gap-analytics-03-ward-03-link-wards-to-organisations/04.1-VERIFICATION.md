## Gaps Summary

**Root cause of BLOCKER:** The phase correctly populates `wards.org_id` via migration 014 (enabling the JOIN), but the `CORP_ANALYTICS_SQL` query uses `ROUND(..., 1)` which PostgreSQL evaluates as type `NUMERIC` (OID 1700). The sqlx 0.7 dependency lacks the `bigdecimal`/`decimal` feature flags needed to decode NUMERIC as `f64`. The handler at line 1460 uses `r.try_get::<f64, _>("resolution_rate_pct").ok()`, which silently converts every type-mismatch error to `None`. The result: the endpoint returns corporation rows with `resolution_rate_pct: null` for all corporations that have reports — meaning ANALYTICS-03 is still non-functional after the migration.

**Fix is a one-line SQL change:** Append `::float8` after the `ROUND(...)` expression in `CORP_ANALYTICS_SQL` to force PostgreSQL to emit OID 701 (`float8`), which sqlx can decode as `f64` natively. No Cargo.toml change required.

**Orphaned requirements:** NF-04.1-A, NF-04.1-B, NF-04.1-C are referenced in both the PLAN frontmatter and ROADMAP but have no canonical definitions in REQUIREMENTS.md. This is a traceability gap — the requirements cannot be audited against their intent.
