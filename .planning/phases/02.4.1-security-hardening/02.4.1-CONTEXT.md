<decisions>
## Implementation Decisions

### Phase Scope
- **D-01:** Scope = both application-level security fixes AND operational security (backup + monitoring + secret rotation docs). All four are production-blocking risks before GBA onboarding.
- **D-02:** Include basic uptime monitoring — a Cloudflare health monitor (or equivalent free-tier uptime check) on `/health`. Self-hosted infra with no monitoring means silent outages are invisible until GBA contacts report a broken experience.
- **D-03:** `admin_get_stats` org-scoping (LOW information exposure) is **Phase 3 scope** — it belongs with the government triage workflow, not here.
- **D-04:** Tech debt cleanup **is in scope**: remove all `TODO: implement` comment headers above functions that are already implemented (`backend/src/models/admin.rs` lines 88, 195, 257, 279, 306, 370, 409, 438, 456; `backend/src/handlers/admin.rs` lines 115, 145), deduplicate bounding box constants (extract to module-level `const`), update stale Railway reference in logout comment (`backend/src/handlers/admin.rs:318`).

### Upload Security
- **D-05:** Accept **JPEG only**. Check for `FF D8` magic bytes in `create_report` handler before any processing. No format conversion — iOS converts HEIC to JPEG before upload and `img-parts` is JPEG-only.
- **D-06:** Non-JPEG uploads return `HTTP 400 BadRequest("Only JPEG images are accepted")` — not a silent fake-success. This is a user-facing validation error, not an abuse signal that needs concealment.
- **D-07:** Magic bytes check lives at the **handler level** in `backend/src/handlers/reports.rs` — consistent with existing validation pattern (bounding box, honeypot). No middleware layer needed.
- **D-08:** Add `add_header Content-Type 'image/jpeg';` to the `/uploads/` location block in **both** `nginx/nginx.conf` and `nginx/nginx.server.conf`. Belt-and-suspenders: even if a non-JPEG file reaches disk, browsers won't execute it as JavaScript.
- **D-09:** Fix the **logout cookie bug**: mirror `SameSite::None` + conditional `Secure` (using the same `cookie_secure` env var read already present in the login handler) onto the removal cookie in `backend/src/handlers/admin.rs:344-351`. Admin logout silently failing on the Vercel + Cloudflare tunnel cross-domain setup is a production bug.

### Data Backup
- **D-10:** Backup destination = `/data` on `sda` (a separate HDD — no cloud dependency). Named Docker volumes for both `postgres_data` and `uploads`.
- **D-11:** PostgreSQL backup via `pg_dump` inside a temporary `postgres:alpine` container. Uploads volume backup via `rsync` from a temporary Alpine container.
- **D-12:** Schedule via **systemd timer** (not a Docker backup service): a `backup/backup.sh` shell script invoked by a weekly `walkability-backup.timer` unit on the host. Simple, auditable, doesn't require a running Docker service.
- **D-13:** **Unconditional weekly backup** — no row-count check or skip logic. `pg_dump` on a small civic DB takes under 5 seconds; conditional logic adds failure modes and can miss non-report DB changes (admin activity, status history).
- **D-14:** **Validation**: check that the `pg_dump` output file is > a minimum size threshold (e.g. 10 KB). On failure, use a systemd `OnFailure=` unit to write a visible journal entry — no email/SMS needed.
- **D-15:** **30-day auto-retention**: script runs `find /data/backups -mtime +30 -delete` after a successful backup. Prevents unbounded disk growth.
- **D-16:** Write a **restore procedure** in `DEPLOYMENT.md` covering: how to restore `pg_dump` output to a fresh container, how to restore the uploads volume, and verification steps.

### Secret Rotation Documentation
- **D-17:** Document secret rotation procedure in `DEPLOYMENT.md`: (1) update GitHub Actions secrets, (2) update `.env` on desktop, (3) `docker compose restart backend` to invalidate current JWTs. Cover `JWT_SECRET`, `POSTGRES_PASSWORD`, and `ADMIN_SEED_PASSWORD`.

### Uptime Monitoring
- **D-18:** Set up a free-tier uptime monitor on `<tunnel-url>/health` (Cloudflare built-in health check, UptimeRobot, or similar). The `/health` endpoint already exists and returns `{"status":"ok"}`. No code changes needed — this is an infrastructure configuration step.

### Claude's Discretion
- Exact plan breakdown (1 vs. 2 vs. 3 plans) — planner decides based on grouping app security vs. ops
- Whether backup script and systemd unit files live in a new `backup/` directory or alongside infra configs
- Exact minimum file size threshold for pg_dump validation (10 KB is a reasonable floor — planner confirms)
- Which specific uptime monitoring service to configure (Cloudflare built-in vs. UptimeRobot — both free, planner picks based on ease of setup)

<specifics>
## Specific Ideas

- Backup destination is `/data` on `sda` — a physically separate HDD from the OS drive. This provides disk-failure isolation without any cloud dependency.
- Uploads volume backup should use a temporary Alpine container with the volume mounted — avoids needing Docker Python SDK or complex tooling; a simple `docker run --rm -v uploads:/data:ro alpine tar czf ...` pattern works.
- Systemd timer for weekly backup is preferable over cron — it integrates with `journalctl` for log visibility and `OnFailure=` units for alerting, both of which are already used for `cloudflared`.
- The TODO comment cleanup should be verified: run `cargo test` after removal to confirm tests still pass (the TODO comments are above implemented functions, not stubs, so no test behavior should change).

</specifics>
