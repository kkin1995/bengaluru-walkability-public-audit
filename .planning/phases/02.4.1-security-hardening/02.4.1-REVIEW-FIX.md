## Fixed Issues

### CR-01: admin_logout — SameSite=None removal cookie rejected without Secure

**Files modified:** `backend/src/handlers/admin.rs`
**Commit:** bafeae3
**Applied fix:** In the `admin_logout` function, added an `else` branch to the `if cookie_secure` block that calls `removal.set_same_site(SameSite::Lax)` when `cookie_secure` is false. This means dev/HTTP environments receive a `SameSite=Lax` removal cookie (accepted by the browser) rather than a `SameSite=None` cookie without `Secure=true` (rejected by the browser per RFC 6265bis, causing logout to silently fail).

---

### WR-01: admin_logout — missing explicit Max-Age=0 on removal cookie

**Files modified:** `backend/src/handlers/admin.rs`
**Commit:** bafeae3
**Applied fix:** Added `.max_age(time::Duration::ZERO)` to the Cookie builder chain for the removal cookie. This ensures `Max-Age=0` is always emitted in the response regardless of whether `CookieJar::remove` finds a matching cookie entry in the jar. CR-01 and WR-01 were applied together as a single coherent change to the same function.

### WR-02: strip_exif fallback silently passes non-JPEG bytes to disk

**Files modified:** `backend/src/handlers/reports.rs`
**Commit:** a16dafe
**Applied fix:** Changed `strip_exif` signature from `fn strip_exif(bytes: &[u8]) -> Vec<u8>` to `fn strip_exif(bytes: &[u8]) -> Result<Vec<u8>, crate::errors::AppError>`. Replaced the `Err(_) => bytes.to_vec()` fallback with `.map_err(|_| AppError::BadRequest("Image processing failed: not a valid JPEG".into()))`. Updated the call site at line 273 to use `?` to propagate the error.

### WR-03: nginx duplicate Content-Type header from add_header

**Files modified:** `nginx/nginx.conf`, `nginx/nginx.server.conf`
**Commit:** d725e2a
**Applied fix:** Replaced `add_header Content-Type "image/jpeg" always` with `add_header X-Content-Type-Options "nosniff" always` in the `/uploads/` location block in both nginx config files. This eliminates the RFC 7230 violation (duplicate Content-Type headers) while still providing MIME sniffing protection.

### CR-02: backup.sh — world-readable backup files (missing umask)

**Files modified:** `backup/backup.sh`
**Commit:** 6869ef2
**Applied fix:** Added `umask 0077` on the line immediately after `set -euo pipefail`. This ensures all backup files are created mode `0600` and all directories mode `0700` (owner-only read/write), preventing world-readable database dumps containing password hashes.

### CR-04: backup.sh — pg_dump password exposure

**Files modified:** `backup/backup.sh`
**Commit:** 6869ef2
**Applied fix:** Added `POSTGRES_PASSWORD=$(grep '^POSTGRES_PASSWORD=' "${REPO_ROOT}/.env" | cut -d= -f2-)` before the `docker exec` call. Changed the `docker exec` invocation to pass `-e "PGPASSWORD=${POSTGRES_PASSWORD}"` as an environment variable scoped only to that call. Added `unset POSTGRES_PASSWORD` immediately after. This ensures the password is never on the command line (visible in `ps aux`) and is cleared from the shell environment as soon as it is no longer needed.

### WR-04: backup.sh — retention find too broad
