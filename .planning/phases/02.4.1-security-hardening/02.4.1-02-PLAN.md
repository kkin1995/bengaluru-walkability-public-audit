<objective>
Add a belt-and-suspenders nginx `Content-Type: image/jpeg` override on the `/uploads/` location block in both nginx configs so the browser will not execute an uploaded asset as script/HTML/SVG even if a non-JPEG somehow reaches disk.

Purpose: Implements D-08 — defense-in-depth alongside the magic-bytes guard from Plan 01. Even if a future regression lets a non-JPEG through the backend, nginx forcing `Content-Type: image/jpeg` prevents browser execution of stored XSS payloads.

Output: Two updated nginx configs plus a manual `curl -I` verification confirming a single `Content-Type: image/jpeg` response header on the deployed tunnel.
</objective>

|----------|-------------|
| Public internet → nginx → `/uploads/` (Axum `ServeDir`) | Browser fetches an uploaded asset; the response's `Content-Type` controls whether the browser executes it as script/HTML/SVG. Trusted server output, but with belt-and-suspenders because uploads originate from untrusted citizens. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02.4.1-04 | Tampering + Elevation of Privilege | nginx `/uploads/` MIME sniffing — if a non-JPEG file (e.g., SVG with `<script>`) reaches disk and nginx serves it with a non-image Content-Type, the browser executes it as script | mitigate | Defense-in-depth nginx `add_header Content-Type "image/jpeg" always;` on the `/uploads/` location block in both nginx.conf and nginx.server.conf. Combined with Plan 01's magic-bytes guard, this is two independent layers preventing stored-XSS. Task 2 checkpoint verifies it lands as a single canonical header on the deployed nginx. |
| T-02.4.1-SC | Tampering | npm/pip/cargo installs | accept | No package installs in this plan — only nginx config edits. Package Legitimacy Gate not applicable. |
