  <action>
    From the project root on the main branch, create the staging branch and push it to the
    remote. Critical: this must be done BEFORE branch protection rules are set (per D-03 and
    research Pitfall 6 — setting protection before the branch exists on remote can block the
    initial push).

    Sequence:
    1. Confirm current branch is main: `git branch --show-current` must print "main"
    2. Create local branch: `git checkout -b staging`
    3. Push to remote: `git push -u origin staging`
    4. Return to main: `git checkout main`

    After push, confirm the branch exists on remote: `git ls-remote --heads origin staging`
    must return a non-empty line.

    Do NOT yet apply branch protection rules — that is a human setup step that follows.
  </action>
  <verify>
    <automated>git ls-remote --heads origin staging | grep -c "refs/heads/staging"</automated>
  </verify>
  <done>
    `git ls-remote --heads origin staging` returns exactly one line containing "refs/heads/staging".
    The staging branch is at the same commit SHA as main at the time of branching.
  </done>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub → self-hosted runner | Workflow YAML instructs runner to SSH into LXC; secrets from GitHub Environments are injected as env vars |
| staging environment → production environment | Two independent GitHub Environments with separate secret sets — no shared values |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01-01 | Information Disclosure | staging secrets match production | mitigate | D-09: staging JWT_SECRET and POSTGRES_PASSWORD MUST be different values from production — generate fresh with openssl rand |
| T-06-01-02 | Elevation of Privilege | branch protection bypass | mitigate | D-07: no admin bypass allowed in branch protection rulesets — all merges require CI + PR |
| T-06-01-03 | Spoofing | staging branch created from wrong commit | mitigate | Task 1 verifies current branch is main before branching; git ls-remote confirms push |
| T-06-01-SC | Tampering | npm/pip/cargo installs | accept | No package manager installs in this plan — git and GitHub UI only |
</threat_model>
