    The document must include ALL of the following sections in this order:

    **1. Overview**
    - Architecture: Vercel (Next.js frontend) + Railway (Rust/Axum backend + PostGIS database)
    - Staging URL: `https://staging-walkability.kinariwala.com`
    - Cost: Railway Hobby plan ($5/mo credit), Vercel free tier
    - nginx is NOT used for staging (Railway handles HTTPS termination)

    **2. Prerequisites**
    - GitHub repository access
    - Railway account (hobby plan)
    - Vercel account (free tier)
    - DNS access to `kinariwala.com` domain

    **3. Step 1: Railway — Provision PostGIS Database**
    - Go to `https://railway.com/new` and create a new project
    - Deploy PostGIS template: click "Deploy Template" and search for "PostGIS" (NOT standard Postgres — standard Postgres does not include PostGIS library files; `CREATE EXTENSION postgis` will fail)
    - URL: `https://railway.com/deploy/postgis`
    - The template deploys Postgres 16 with PostGIS 3.4 and pgcrypto pre-installed
    - After the PostGIS service is running, note the `DATABASE_PRIVATE_URL` from the Variables tab (or use the `${{Postgres.DATABASE_PRIVATE_URL}}` reference syntax for the backend service)

    **4. Step 2: Railway — Deploy Backend Service**
    - In the same Railway project, click "New Service" and select "GitHub Repo"
    - Select the `bengaluru-walkability-public-audit` repository
    - Set Root Directory to `backend` (this makes Docker build context = `backend/`, required for the Dockerfile's COPY commands)
    - Railway will detect the Dockerfile automatically (aided by `backend/railway.toml` committed in Plan 02)
    - Set all environment variables (see checklist below)
    - For `DATABASE_URL`, use Railway's internal reference: `${{Postgres.DATABASE_PRIVATE_URL}}`
    - After first deploy, note the public URL (e.g., `https://walkability-api.up.railway.app`) — needed for Vercel and GitHub Actions setup
    - Verify: check Railway deploy logs for "Listening on 0.0.0.0:PORT" and "Admin seed: seeded admin user" (or "admin already exists" on subsequent boots)

    **5. Step 3: Vercel — Deploy Frontend**
    - Go to `https://vercel.com/new` and import the GitHub repository
    - Before deploying, click "Edit" next to Root Directory and set to `frontend`
    - Vercel will auto-detect Next.js
    - Set environment variables (see checklist below) — set in BOTH Production and Preview scopes
    - `NEXT_PUBLIC_API_URL` MUST be set to the Railway backend public URL (from Step 2) BEFORE the first build. This variable is baked at build time.
    - `INTERNAL_API_URL` must also be set to the Railway backend public URL
    - Trigger deploy (Vercel deploys automatically on import)

    **6. Step 4: DNS — Configure Custom Domain**
    - In Vercel Dashboard: Project > Settings > Domains > Add > `staging-walkability.kinariwala.com`
    - Vercel will display the required DNS record (typically a CNAME)
    - At DNS registrar for `kinariwala.com`: add CNAME record `staging-walkability` pointing to `cname.vercel-dns.com` (use the exact value Vercel shows — it may be project-specific like `d1d4fc829fe7bc7c.vercel-dns-017.com`)
    - DNS propagation: typically 5-30 minutes
    - Vercel auto-provisions TLS (Let's Encrypt) once DNS resolves
    - After DNS propagates: `https://staging-walkability.kinariwala.com` should load the frontend

    **7. Step 5: GitHub Actions — Configure Secrets**
    - Go to GitHub repository > Settings > Secrets and variables > Actions
    - Add repository secret: `RAILWAY_BACKEND_URL` = the Railway backend's public URL (e.g., `https://walkability-api.up.railway.app`)
    - This enables the smoke test job in `.github/workflows/deploy.yml` to verify staging health after each push to main

    **8. Deployment Ordering (CRITICAL)**
    - Railway MUST be provisioned and running BEFORE Vercel builds the frontend
    - Reason: `NEXT_PUBLIC_API_URL` is baked into the frontend at build time. If the Railway URL is not set when Vercel builds, all client-side API calls will fail.
    - Order: Railway PostGIS DB > Railway Backend > Vercel Frontend > DNS
    - If Railway URL changes: update `NEXT_PUBLIC_API_URL` and `INTERNAL_API_URL` in Vercel project settings, then trigger a new Vercel deploy (Settings > Deployments > Redeploy)

    **9. Environment Variable Checklist**

    Railway Backend Service:

    | Variable | Value | Notes |
    |----------|-------|-------|
    | `DATABASE_URL` | `${{Postgres.DATABASE_PRIVATE_URL}}` | Railway internal reference to PostGIS service |
    | `JWT_SECRET` | (generate: `openssl rand -hex 32`) | Min 32 characters. Keep secret. |
    | `COOKIE_SECURE` | `true` | Required for SameSite=None cookies over HTTPS |
    | `CORS_ORIGIN` | `https://staging-walkability.kinariwala.com` | Exact match, no trailing slash, no wildcard |
    | `UPLOADS_DIR` | `./uploads` | Ephemeral on Railway (lost on redeploy) — acceptable for UAT |
    | `PORT` | `3001` | Railway also injects PORT; explicit value ensures consistency |
    | `RUST_LOG` | `info` | Logging level for tracing subscriber |
    | `ADMIN_SEED_EMAIL` | (choose staging admin email) | Creates initial super-admin on first boot |
    | `ADMIN_SEED_PASSWORD` | (choose strong password, min 12 chars) | Used only for initial seed; change via UI after |

    Vercel Frontend:

    | Variable | Value | Scope | Notes |
    |----------|-------|-------|-------|
    | `NEXT_PUBLIC_API_URL` | `https://walkability-api.up.railway.app` (example) | Production + Preview | Railway backend public URL. Baked at build time. |
    | `INTERNAL_API_URL` | `https://walkability-api.up.railway.app` (example) | Production + Preview | Same Railway URL. Used by server-side fetches and Next.js rewrites. |

    GitHub Actions:

    |--------|-------|-------|

    **10. Pre-UAT Verification Checklist**

    Run through this checklist BEFORE sharing the staging URL with GBA/Walkaluru partners:

    - [ ] Railway backend is deployed and healthy: `curl -f https://<railway-url>/health`
    - [ ] PostGIS is working: Railway deploy logs show successful migration (no "postgis.control" errors)
    - [ ] Admin seed ran: Railway deploy logs show "Admin seed" message
    - [ ] Vercel frontend loads: `https://staging-walkability.kinariwala.com` shows the app
    - [ ] HTTPS is active: browser shows padlock icon on staging URL
    - [ ] Admin login works: navigate to `https://staging-walkability.kinariwala.com/admin/login`, enter seed credentials, confirm redirect to `/admin/reports`
    - [ ] Admin cookie is set: after login, browser DevTools > Application > Cookies shows `admin_token` under `staging-walkability.kinariwala.com`
    - [ ] Admin pages are protected: open an incognito window, navigate to `https://staging-walkability.kinariwala.com/admin/reports` — should redirect to login
    - [ ] Public report submission works: navigate to `https://staging-walkability.kinariwala.com/report`, submit a test photo with GPS coordinates
    - [ ] Reports appear on map: navigate to `https://staging-walkability.kinariwala.com/map`, confirm the test report pin appears
    - [ ] CI smoke test passes: trigger `workflow_dispatch` in GitHub Actions, confirm the Deploy workflow succeeds

    **11. Known Limitations**

    - **Ephemeral uploads:** Railway does not persist the `uploads/` directory across redeploys. Uploaded photos are lost when the backend container restarts. This is acceptable for UAT (per D-03). For production, either provision a Railway persistent volume or switch to S3/R2 object storage.
    - **Single CORS origin:** `CORS_ORIGIN` accepts exactly one origin. If you need to test from both `staging-walkability.kinariwala.com` and the Vercel auto-assigned `*.vercel.app` URL, update `CORS_ORIGIN` to match whichever URL you are using. Only one can be active at a time without code changes.
    - **Build-time API URL:** `NEXT_PUBLIC_API_URL` is baked at build time. Changing the Railway URL requires a Vercel redeploy.
    - **Railway cold start:** The first request after a period of inactivity may take 5-15 seconds while Railway's container spins up.

    **12. Troubleshooting**

    | Symptom | Likely Cause | Fix |
    |---------|-------------|-----|
    | Frontend shows blank page / API 404s | `NEXT_PUBLIC_API_URL` not set or wrong | Set correct Railway URL in Vercel env vars, redeploy |
    | Admin login succeeds but immediately redirects to login again | Cookie domain mismatch | Verify admin API calls go through `/api/admin/*` (Vercel rewrite), not directly to Railway |
    | `CREATE EXTENSION postgis` fails in migration | Using standard Railway Postgres, not PostGIS template | Delete Postgres service, deploy PostGIS template instead |
    | Smoke test fails in CI | `RAILWAY_BACKEND_URL` secret not set, or Railway still deploying | Add secret in GitHub Settings; wait and re-run |
    | CORS error in browser console | `CORS_ORIGIN` on Railway does not match browser URL | Set `CORS_ORIGIN` to exact staging URL including `https://` |
    | Photos disappear after redeploy | Ephemeral uploads on Railway | Expected behavior for UAT. Re-upload test photos after redeploy. |
