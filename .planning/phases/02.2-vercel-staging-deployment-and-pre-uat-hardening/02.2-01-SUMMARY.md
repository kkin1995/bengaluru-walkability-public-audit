# Phase 02.2 Plan 01: Cross-Domain Admin Auth Fix Summary

**One-liner:** SameSite=None cookie + Next.js rewrites proxy for admin API enabling Vercel+Railway cross-domain auth.

## What Was Built

Fixed the broken admin login flow for the Vercel + Railway split-domain deployment. When frontend (Vercel) and backend (Railway) are on different domains, the existing `SameSite=Strict` cookie was silently rejected by browsers. The fix operates at two layers:

1. **Backend (admin.rs):** Changed `SameSite::Strict` to `SameSite::None` so the cookie is accepted in cross-origin contexts. `SameSite=None` requires `Secure=true`, which is already enforced by the existing `COOKIE_SECURE=true` environment variable in staging/production.

2. **Frontend (next.config.mjs):** Added `rewrites()` function that proxies all `/api/admin/*` requests through Vercel to the Railway backend. This makes the browser see the admin API responses as coming from the Vercel domain, so the `Set-Cookie` header sets the cookie on the Vercel domain — which is then readable by `middleware.ts`.

3. **Frontend (config.ts):** Added `ADMIN_API_BASE_URL = ""` export — a hardcoded empty string (not an env var). Admin client-side code now uses this, making all admin API calls relative URLs (`/api/admin/...`) that hit the Vercel rewrite proxy.

4. **Frontend (adminApi.ts, login/page.tsx):** Updated imports to use `ADMIN_API_BASE_URL` instead of `API_BASE_URL`. Public API calls (`API_BASE_URL`) continue pointing directly to Railway for 20MB photo uploads.
