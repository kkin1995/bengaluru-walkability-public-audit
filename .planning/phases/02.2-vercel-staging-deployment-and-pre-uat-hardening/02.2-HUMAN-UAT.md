## Issues Found

### BUG-01: Admin reports table shows raw enum instead of display name
**Severity:** Medium  
**Screen:** Admin > Reports table (IMG_4192)  
**Observed:** Category column shows `broken_footpath` (snake_case DB enum). The public-facing app displays "Damaged Footpath" and the map popup also shows "Damaged Footpath". Admin should render the same human-readable label.  
**Expected:** "Damaged Footpath" (or at minimum "Broken Footpath")  
**Note:** The map legend (IMG_4187) uses a third variant — "Broken" — for the same category. Three different labels for one category across three surfaces.

---

### BUG-02: iOS file picker creates redundant UX on "Take Photo" button
**Severity:** Low  
**Screen:** Step 1 of 4 — Photo (IMG_4180)  
**Observed:** Tapping the green "Take Photo" button triggers the iOS native action sheet with three options: "Photo Library", "Take Photo", "Choose File". There is also a second button below labelled "Upload from Gallery" which presumably triggers a similar or identical picker. The two-button design (Take Photo vs Upload from Gallery) becomes one picker on iOS, confusing the intended distinction.  
**Expected:** Either a single button that triggers the native picker, or two distinct pickers that each open to a different state (camera-first vs gallery-first).  
**Note:** This is a mobile browser limitation — `<input type="file">` always shows the full iOS sheet. Consider using `capture="environment"` on the camera button and a separate file input without `capture` for the gallery button.

---

### UX-01: Admin reports table overflows horizontally on mobile portrait
**Severity:** Low  
**Screen:** Admin > Reports table (IMG_4192)  
**Observed:** The table has columns CATEGORY, SEVERITY, STATUS, WARD and the Ward column is cut off showing "Sagayap..." (should be "Sagayapura"). Users need to scroll horizontally to see all columns, but there is no visual affordance indicating this.  
**Expected:** Either a horizontal scroll indicator, or a responsive card-per-row layout for mobile viewports.

---

### UX-02: Admin sidebar has no visible menu trigger on mobile portrait
**Severity:** Low  
**Screen:** Admin Dashboard on mobile (IMG_4190 vs IMG_4191)  
**Observed:** On mobile portrait, the sidebar is hidden and the dashboard shows without any navigation (IMG_4190). The user had to use an undiscoverable gesture or tap to reveal the sidebar (IMG_4191). No hamburger/menu icon is visible in the header.  
**Expected:** A visible ☰ hamburger button in the admin header so mobile users can access navigation.

---

### UX-03: Map legend label inconsistent with submission form
**Severity:** Low  
**Screen:** Public map legend (IMG_4187)  
**Observed:** The legend shows "Broken" for the category the submission form calls "Damaged Footpath". Three surfaces, three labels: submission form ("Damaged Footpath"), map legend ("Broken"), admin table ("broken_footpath").  
**Expected:** Consistent label "Damaged Footpath" across all three surfaces.
