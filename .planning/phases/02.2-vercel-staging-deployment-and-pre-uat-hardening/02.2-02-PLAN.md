    The deploy job is renamed to `smoke-test` because Railway and Vercel auto-deploy via their own GitHub integrations (per D-09) — this workflow only verifies staging is healthy AFTER the platforms redeploy.

    ```yaml
    name: Deploy

    on:
      push:
        branches:
          - main
      workflow_dispatch:

    jobs:
      ci:
        name: "Run CI checks"
        # Reuse the canonical CI workflow so deploy never ships code that has not
        # passed lint, tests, and docker-build verification.
        uses: ./.github/workflows/ci.yml

      smoke-test:
        name: "Smoke test staging"
        needs: ci
        runs-on: ubuntu-latest
        # Only run smoke tests when secrets are configured.
        # Forks and first-time setups without secrets will skip gracefully.
        if: ${{ secrets.RAILWAY_BACKEND_URL != '' }}
        env:
          RAILWAY_BACKEND_URL: ${{ secrets.RAILWAY_BACKEND_URL }}
          VERCEL_STAGING_URL: https://staging-walkability.kinariwala.com
        steps:
          - name: Wait for Railway and Vercel redeploy to start
            run: sleep 30

          - name: "Health check - Railway backend (with retry)"
            run: |
              for i in 1 2 3 4 5; do
                if curl -sf --max-time 10 "$RAILWAY_BACKEND_URL/health"; then
                  echo ""
                  echo "Backend healthy on attempt $i"
                  exit 0
                fi
                echo "Attempt $i/5 failed, retrying in 15s..."
                sleep 15
              done
              echo "Backend health check failed after 5 attempts"
              exit 1

          - name: "API check - Railway reports endpoint"
            run: |
              response=$(curl -sf --max-time 10 "$RAILWAY_BACKEND_URL/api/reports")
              echo "Reports endpoint responded: $(echo "$response" | head -c 200)"

          - name: "Frontend check - Vercel staging"
            run: |
              status=$(curl -sf --max-time 15 -o /dev/null -w "%{http_code}" "$VERCEL_STAGING_URL")
              echo "Vercel staging HTTP $status"
              if [ "$status" -ne 200 ]; then
                echo "Expected HTTP 200, got $status"
                exit 1
              fi
    ```

    **Key design decisions:**
    - `if: ${{ secrets.RAILWAY_BACKEND_URL != '' }}` — the smoke-test job skips gracefully if the secret is not configured yet (first-time setup, forks). This prevents CI failures before Railway is provisioned.
    - `sleep 30` before the retry loop — gives Railway time to start the redeploy after the push event (Railway deploys asynchronously from GitHub Actions).
    - Retry loop: 5 attempts x 15s = 75s additional wait. Total wait: ~105s. Covers Railway cold-start for a Rust Docker build with cache.
    - `--max-time 10` on curl — prevents hanging on unresponsive endpoints.
    - The `VERCEL_STAGING_URL` is hardcoded to `https://staging-walkability.kinariwala.com` (per D-04) rather than a secret, since the domain is public and not sensitive.

    **Required GitHub Actions secret (manual setup, documented in STAGING-SETUP.md):**
    - `RAILWAY_BACKEND_URL` — the Railway backend's public URL (e.g., `https://walkability-api.up.railway.app`). Set this after the first Railway deploy.

    Create a new file `backend/railway.toml` with Railway config-as-code. Per the research (Pattern 1), when Railway's service Root Directory is set to `backend`, the `dockerfilePath` is relative to that root — so it is just `Dockerfile`, not `backend/Dockerfile`.

    The complete file:

    ```toml
    # Railway config-as-code for the Rust/Axum backend service.
    # Railway service settings: Root Directory = "backend"
    # See: https://docs.railway.com/reference/config-as-code

    [build]
    builder = "DOCKERFILE"
    dockerfilePath = "Dockerfile"

    [deploy]
    healthcheckPath = "/health"
    healthcheckTimeout = 300
    restartPolicyType = "ON_FAILURE"
    restartPolicyMaxRetries = 5
    ```

    **Design decisions:**
    - `healthcheckPath = "/health"` — the backend already has a `GET /health` endpoint (confirmed in CLAUDE.md API endpoints table).
    - `healthcheckTimeout = 300` — 5 minutes. Rust Docker builds are slow on first deploy; subsequent builds use layer cache. Railway kills unhealthy containers after this timeout.
    - `restartPolicyType = "ON_FAILURE"` with max 5 retries — Railway restarts crashed containers up to 5 times. Beyond that, manual investigation needed.
    - No `watchPatterns` — Railway's GitHub integration watches the entire repo by default. The Root Directory setting (`backend`) is sufficient to scope builds. Adding watchPatterns would prevent redeploys when shared files outside `backend/` change (e.g., migrations, docker-compose reference files). Omitting is the safer default.
