<schema_correction priority="critical">
The phase CONTEXT.md and the UAT gap notes describe the `status_history` columns
as `changed_by_id, old_status, changed_at, notes`. THIS IS WRONG. The actual
schema (migration 001_init.sql lines 70-77 + migration 002_admin.sql lines
25-26) is:

  status_history (
    id          UUID PRIMARY KEY,
    report_id   UUID NOT NULL REFERENCES reports(id) ON DELETE CASCADE,
    old_status  report_status,            -- nullable
    new_status  report_status NOT NULL,
    changed_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    note        TEXT,                       -- SINGULAR "note", not "notes"
    changed_by  UUID REFERENCES admin_users(id) ON DELETE SET NULL  -- "changed_by", not "changed_by_id"
  )

Use the REAL column names: `changed_by` (not `changed_by_id`) and `note` (not
`notes`). Verify against the two migration files before writing any SQL. The
existing INSERT statements in admin_queries.rs (update_report_status,
resolve_report, assign_report_org) already use `note` and `changed_by` — match them.

There is NO `cargo sqlx prepare` step required for this plan. The file header
comment in admin_queries.rs (lines 1-11) states all queries use runtime
`sqlx::query` / `sqlx::query_as`, NOT compile-time macros, and the repo has no
`.sqlx` offline cache directory. Do NOT run `cargo sqlx prepare` — it is
unnecessary and would require a live DB. `cargo test` and `cargo check` are the
verification gates.
</schema_correction>
