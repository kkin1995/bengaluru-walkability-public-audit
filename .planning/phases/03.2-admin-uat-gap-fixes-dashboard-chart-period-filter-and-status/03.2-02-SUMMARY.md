# Phase 03.2 Plan 02: Frontend Gap Fixes — Dashboard Period Filter and Status History Attribution Summary

Frontend half of BUG-03.1-B and BUG-03.1-C closed: dashboard period buttons are now interactive with active-state tracking and recomputed sparkbars, and the status timeline on the report detail page renders real audit-trail entries from `status_history` instead of the hardcoded `BY · SYSTEM` placeholder.

## What Was Built

**Task 1 — adminApi.ts (D-07, D-08):**

- Exported new `StatusHistoryEntry` interface with 7 fields matching backend JSON shape exactly: `id`, `old_status` (string | null), `new_status`, `changed_at`, `note` (string | null), `changed_by` (string | null), `changed_by_name` (string | null)
- Added optional `status_history?: StatusHistoryEntry[]` field to the existing `AdminReport` interface — optional so the fallback path type-checks when the field is absent
- Existing `updated_at: string` field preserved unchanged

**Task 2 — report detail page.tsx (D-07):**

- Imported `StatusHistoryEntry` type from adminApi
- Extracted `statusDotColor(status: string): string` helper that replaces the duplicated 6-branch inline switch used for both the `data-status-token` attribute and `background` style
- Replaced the hardcoded `{formatDate(report.updated_at)} · BY · SYSTEM` with a conditional renderer:
  - When `report.status_history` is a non-empty array: `.map` over entries, rendering each with the status dot (keyed off `entry.new_status`), label (`entry.new_status.replace(/_/g, " ")`), date (`formatDate(entry.changed_at)`), and attribution (`entry.changed_by_name || "—"` — never "SYSTEM")
  - Optional `entry.note` rendered as secondary italic line when present
  - Fallback (empty or undefined): single current-status row using `report.status` and `formatDate(report.updated_at)` with attribution `"—"`
- Added 7 new tests covering: 2-entry history renders 2 dots, Priya Rao attribution visible, SYSTEM never appears, null changed_by_name shows "—", Invalid Date never appears, empty-history fallback, undefined-history fallback

**Task 3 — admin dashboard page.tsx (D-01, D-02, D-03):**

- Added `const [activePeriod, setActivePeriod] = useState<"7D" | "14D" | "30D">("14D")`
- Each period label wrapped in `<button type="button" onClick={() => setActivePeriod(label)}>` with reset styling (no border/background, cursor:pointer)
- Pill tone now driven by `label === activePeriod` (not the hardcoded `label === "14D"`)
- `sparkbarsValues` computed from `activePeriod`: slice last 7/14 values of STUB_SPARKBARS or cyclically pad to 30 — chart visibly changes without fabricating backend data
- Section label updates to reflect period: `Intake · 7_Day` / `Intake · 14_Day` / `Intake · 30_Day`
- Added 4 new tests: period buttons present, 14D active by default, click 7D → 7D accent + 14D outline, click 30D → 30D accent

## Known Stubs

- `sparkbarsValues` is still derived from `STUB_SPARKBARS` (a fixed 14-element array). The stub is documented and intentional: the plan explicitly notes "This delivers the D-01 behavior exactly — clickable buttons, active-state tracking, and a recomputed chart window on change.
