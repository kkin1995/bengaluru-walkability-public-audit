- id: BUG-03.2-A
  truth: "INTAKE chart sparkbars reflect actual per-day report counts for the selected period"
  status: resolved
  test: 1
  severity: major
  root_cause: |
    The sparkbars derive from STUB_SPARKBARS — a hardcoded 14-element array [3,5,2,8,6,4,9,7,5,3,6,8,4,5].
    For 7D it slices the last 7 values; for 30D it cyclically pads to 30 — so with 1 real report in
    the system, the bars show heights of 3–9 which is meaningless. The wiring (period state →
    sparkbarsValues → Sparkbars) is correct and reusable; only the data source needs replacing.
  artifacts:
    - path: "frontend/app/admin/page.tsx:103-115"
      issue: "sparkbarsValues derived from STUB_SPARKBARS constant, not real per-day intake data"
    - path: "backend/src/db/admin_queries.rs"
      issue: "no per-day intake series endpoint exists; GET /api/admin/stats returns only aggregate counts"
  fix_direction: |
    Backend: add GET /api/admin/stats/intake?days=N returning per-day counts via
    SELECT date_trunc('day', created_at) AS day, COUNT(*) AS count FROM reports
    WHERE created_at >= NOW() - INTERVAL '$1 days' GROUP BY 1 ORDER BY 1.
    Frontend: replace sparkbarsValues IIFE with a useEffect that fetches the endpoint
    when activePeriod changes, filling sparse days with 0.
  deferred_to: "03.3"

- id: BUG-03.2-B
  truth: "Status history entries show the name of the admin who made the change"
  status: resolved
  test: 2
  severity: major
  root_cause: |
    The backend SELECT uses au.display_name AS changed_by_name with no fallback. The seeded admin
    account (and all test accounts) have display_name = NULL. The changed_by UUID is correctly stored
    in status_history rows (handlers extract it from JWT at admin.rs:502, 704, 750), so the LEFT JOIN
    finds the right admin_users row — but display_name is NULL, so changed_by_name returns NULL and
    the frontend shows '—'. The fix is a single COALESCE in the backend query.
  artifacts:
    - path: "backend/src/db/admin_queries.rs:546"
      issue: "au.display_name AS changed_by_name — no COALESCE fallback to au.email when display_name is NULL"
  fix_direction: |
    Backend one-liner: change au.display_name to COALESCE(au.display_name, au.email) AS changed_by_name
    in the status_history SELECT inside get_admin_report_by_id. No frontend change needed.
  deferred_to: "03.3"
