### 1. Home page visual design
expected: |
  Open http://localhost:3000 (or staging URL).
  You should see:
  - Header: small dark square with a white pin icon, "Namma ದಾರಿ" in bold, "Walkable BLR" in small mono text, and "EN · ಕ" language toggle (display only, not interactive)
  - Hero: a small section label "CITIZEN AUDIT · ನಾಗರಿಕ", a large heading "Fix the footpath.", and two lines of sub-text below it
  - Map preview: a grey map-tile box (~180px tall) with 10 coloured dots scattered on it, a glass pill reading "412 reports", and an "Open map →" link
  - Primary CTA: a large accent-coloured button with a camera icon and bilingual text "Report an issue / ಸಮಸ್ಯೆ ವರದಿ ಮಾಡಿ"
  - Trust copy: "No login · Takes 20 seconds · Anonymous" in muted grey below the button
  - Background is a warm off-white (not bright white, not green gradient from the old design)
result: pass
note: Large empty gap above hero on desktop viewport — intentional mobile-first layout, not a blocker

### 2. Map page full-bleed layout
expected: |
  Click "Open map →" from the home page (or navigate to /map).
  You should see:
  - The map fills the full screen edge-to-edge with no white header bar above it
  - A floating top bar overlaid on the map (not pushing it down): a circle back-arrow button on the left, a pill showing "Bengaluru" in the centre, and a filter-icon circle button on the right
  - A floating "Report here" accent pill button in the bottom-right corner
  - No colour-legend strip (the old "Green = Reported, Orange = Investigating" strip should be gone)
  - Existing report markers still appear on the map
result: issue
reported: "Leaflet +/- zoom buttons in top-left partially block the floating back button in the overlay bar"
severity: minor

### 3. Report flow — Photo step
expected: |
  Click the "Report an issue" CTA on the home page (or navigate to /report).
  You should see a photo capture screen with:
  - A large tappable area (or file input styled as a card) to select or take a photo
  - On mobile: tapping it should offer the camera
  - After selecting a photo: a preview of the image appears and a brief "Processing…" indicator may show (it processes EXIF GPS silently)
  - The step indicator or layout should make it clear this is step 1 of the flow
result: issue
reported: "Implementation has a separate STEP 1 · PHOTO page with two card buttons (Take Photo / Upload from Gallery). UI-SPEC says home page CTA should be a file input label that directly opens camera, and the first /report screen should be the Category Picker with photo thumbnail already shown. Extra step not in spec."
severity: major

### 4. Report flow — Category step
expected: |
  After selecting a photo, you should advance to the category selection screen.
  You should see:
  - A 3-column grid of 6 category chips: "No path / ದಾರಿಯಿಲ್ಲ", "Damaged / ಹಾಳು", "Blocked / ತಡೆ", "Crossing / ದಾಟು", "Lighting / ಬೆಳಕು", "Other / ಇತರ"
  - Each chip has an icon and bilingual label
  - Tapping a chip highlights it (dark ink background, white text, check badge)
  - Only one chip can be selected at a time
  - A "Next" or "Continue" button becomes enabled after selecting a category
result: pass

### 5. Report flow — Confirm step
expected: |
  After selecting a category, you should advance to the confirm/details screen.
  You should see:
  - A severity selector with 3 options: Low (green-ish), Medium (amber/warn), High (red/danger) — tapping one selects it
  - An optional notes/description textarea
  - A collapsible contact section (for name/email, collapsed by default)
  - A small map tile preview showing the report location with an "Adjust" or map pin option
  - A "Submit report" button at the bottom
result: issue
reported: "Two issues: (1) Category shows raw enum 'no_footpath' instead of human label 'No path' in the review card. (2) 'Add contact for follow-up (private)' accordion does not open when clicked anywhere on it."
severity: major

### 6. End-to-end submission and success card
expected: |
  Complete the full flow (photo → category → confirm) and tap "Submit report".
  If the backend is running:
  - A brief loading/submitting state appears
  - On success: the screen transitions to a success card showing "Thank you. It's on the map." (or similar), a Report ID number, a Share button, and a "Report another" CTA
  - Tapping "Report another" returns you to the photo step
  If the backend is NOT running:
  - An error message should appear (not a blank/stuck screen) explaining the submission failed
result: issue
reported: "Submission succeeded and success card content is correct, but SuccessCard renders full-width on desktop while the rest of the report flow is constrained to ~428px centered. Missing max-width container on the success screen."
severity: cosmetic

  - Section label: "CITIZEN AUDIT" / "ನಾಗರಿಕ"
