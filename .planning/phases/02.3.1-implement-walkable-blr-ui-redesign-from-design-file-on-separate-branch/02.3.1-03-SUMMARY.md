# Plan 02.3.1-03 Summary — Report 2-Step Flow Redesign

## What Was Built

Rewrote the `/report` page from a 4-step wizard (Photo → Location → Category → Details) to a streamlined 2-step flow (Photo → Category → Confirm → Success), matching UI-SPEC Screens 2–4. Three new feature components were created under `frontend/app/components/redesign/`.

## Task 1: CategoryGrid, SeverityGrid, SuccessCard + Tests

**New components under `frontend/app/components/redesign/`:**

- **CategoryGrid** — 3-column radio chip grid with 6 categories (no_footpath, broken_footpath, blocked_footpath, unsafe_crossing, poor_lighting, other). Active chip uses `background: var(--ink)` (not accent — deliberate UI-SPEC choice). Each chip shows a bilingual `<Bi>` label + category icon + check badge when selected.
- **SeverityGrid** — 3-column radio grid (low/medium/high) with semantic color coding: accent-bg (low), warn-bg (medium), danger-bg (high). Hint text updates below grid to describe severity impact.
- **SuccessCard** — Success screen with check_circle badge, "Thank you. It's on the map." h1, Report ID card, Share button (Web Share API with clipboard fallback), Report another CTA.

**47 unit tests pass** across 3 test files.

## Task 2: Report Page Rewrite + Test Rewrite

**State shape decision:** Single `"use client"` page with `type Step = "photo" | "category" | "confirm"` union. Same `FormState` interface as before (backend API contract preserved). `submittedReportId !== null` triggers SuccessCard render branch.

**2-step flow mapping (old → new):**
- Old Step 1 (Photo) + Old Step 2 (Location) → New photo step: label-wrapped file inputs, EXIF GPS extracted silently, GPS pill shown on category step
- Old Step 3 (Category) → New category step (Step 1 of 2)
- Old Step 4 (Details: severity + notes + contact) → New confirm step (Step 2 of 2): severity grid + note textarea + contact collapse (display only) + map-tile preview with Adjust button

**Preserved functional behavior:**
- `capture="environment"` on label-wrapped camera input (Phase 02.3 iOS Safari pattern)
- `exifr.gps(originalFile)` called before compression (Phase 02.2 decision — canvas re-encoding strips EXIF)
- `compressImage()` inlined — same quality loop as PhotoCapture.tsx (10MB threshold, 6 quality steps)
- `isInBengaluru()` out-of-bounds guard — blocks submission when lat/lng outside Bengaluru bbox
- Honeypot `<input name="website">` with `position:absolute; left:-9999px` on ALL steps (ABUSE-02)
- FormData submission with all required fields: photo, lat, lng, category, severity, location_source, website + optional description, name, contact

**PhotoCapture.tsx untouched** — kept in repo for backward compatibility; its own 14-test suite still passes.

**TypeScript fix:** SuccessCard share handler used `typeof navigator !== "undefined"` twice in an if/else-if, causing TypeScript to narrow `navigator` to `never` in the else-if branch. Fixed by capturing `const nav = typeof navigator !== "undefined" ? navigator : null` and using `"share" in nav` / `"clipboard" in nav` string-keyed checks with explicit Navigator cast.
