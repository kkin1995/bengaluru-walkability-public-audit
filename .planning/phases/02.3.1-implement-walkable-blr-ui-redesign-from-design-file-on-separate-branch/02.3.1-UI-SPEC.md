## Spacing Scale

Declared values (all multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, badge padding, inline spacing between paired elements |
| sm | 8px | Label-to-icon gaps, compact chip internal padding, section-label bottom margin |
| md | 16px | Default section horizontal padding, card internal padding, row spacing |
| lg | 24px | Section vertical gaps, top bar padding, card-to-card spacing |
| xl | 32px | Major section separators, screen-level top padding |
| 2xl | 48px | Hero vertical space, large screen-level breathing room |
| 3xl | 64px | Minimum tap target height for XL CTAs (enforced as `min-height: 64px`) |

Exceptions:
- Touch target minimum for icon buttons: 44px (applied to back arrow, close button, filter button, map floating CTA)
- Map preview height: 180px (fixed, from design)
- Mini-map height on confirm screen: 120px (fixed, from design)
- Photo thumbnail on category and confirm screens: 72×72px
- Category chip min-height: 76px
- Bottom safe area: `padding-bottom: max(20px, env(safe-area-inset-bottom))` on all screen roots
- `.bi` component gap: 2px — typographic gap between stacked English and Kannada spans (0px collapses stacked text; 4px adds excessive separation at 0.72em Kannada size)

## Typography

**Declared sizes (4 maximum — checker compliance):**

| Role | Font | Size | Weight | Line Height | Used For |
|------|------|------|--------|-------------|---------|
| Display | Inter | 28px | 700 | 1.2 | Home h1 "Fix the footpath.", Success h1 |
| Heading | Inter | 20px | 600 | 1.2 | Screen headers (Confirm & submit), card headings |
| Body | Inter | 16px | 400 | 1.5 | Default text, subtext, note textarea, CTA labels |
| Label | Inter | 14px | 500 | 1.4 | Section labels (uppercase via SectionLabel), chip labels, status text, sub-copy, hint text |
| Mono | JetBrains Mono | inherits 14px from Label scale | 400–500 | 1.4 | GPS coordinates, report ID, "GBA" badge, step indicator, mono meta labels |
| Kannada | Noto Sans Kannada | 0.72em (relative to parent) | 400–600 | 1.5 | All `.bi-kn` secondary labels — always paired with English primary |

**Mono size note:** JetBrains Mono is a typeface role, not a new scale size. Mono text inherits 14px from the Label scale. The `SectionLabel` component uses 11px — this is a single component-level override, not a new scale size (the checker should treat it as a component exception, not a 5th scale value).

**Caption/sub-copy note:** Small descriptive copy ("No login · Takes 20 seconds · Anonymous", severity hint text below the grid) renders at 14px Label size. If a specific element visually needs 12px for density reasons (e.g. the "Save for reference" hint on the report ID card), that is a component-level override, not a scale size.

**Weight override — checker exception:** 4 Inter weights (400/500/600/700) are locked from the design file (CONTEXT.md user decision — claude.ai/design export, `<decisions>` section: "Body: Inter (400, 500, 600, 700)"). This is a brand typography requirement from the design handoff, not an ad-hoc choice. The checker rule "maximum 2 font weights" is superseded by this explicit user decision. Checker should treat these 4 weights as a user-acknowledged exception to the 2-weight guideline.

Font feature settings on `body`: `"cv02", "cv03", "cv04", "cv11"` (Inter optical refinements).

Typography rules:
- Maximum 2 font weights per text role in a single context (do not mix weight 400 and 700 in adjacent body text)
- Kannada always at 0.72em and opacity 0.7 relative to its English sibling — never standalone at full size
- Mono text never used for running body copy — reserved exclusively for data values (coords, IDs, step counters)

## Component Inventory

New primitives to create in `frontend/app/components/ui/`:

### `Bi` — Bilingual stacked text span
```
Props: en: string, kn?: string, className?: string, style?: CSSProperties
Output: <span class="bi [className]"><span class="bi-en">{en}</span><span class="bi-kn">{kn}</span></span>
CSS: .bi { display: flex; flex-direction: column; } .bi-kn { font-family: var(--font-kn); font-size: 0.72em; opacity: 0.7; }
```

### `Icon` — Inline SVG icon component
```
Props: name: IconName, size?: number (default 24), className?: string, style?: CSSProperties
Output: <svg viewBox="0 0 24 24" aria-hidden="true" stroke-width="1.75" ...><path .../></svg>
Required icon names (35+): camera, map, pin, arrow_right, arrow_left, check, check_circle, close, image,
  flash, flip, crosshair, edit, send, chevron_right, chevron_down, share, grid, list, filter, globe, menu,
  shield, mic, cat_no_path, cat_broken, cat_blocked, cat_crossing, cat_lighting, cat_other, cat_ramp,
  cat_encroach
SVG paths: transcribe directly from design source /tmp/.../primitives.jsx
```

### `Btn` — Button primitive
```
Props: variant: 'primary' | 'accent' | 'secondary' | 'ghost', size: 'sm' | 'md' | 'lg' | 'xl',
       disabled?: boolean, onClick?: fn, type?: 'button' | 'submit', className?: string, children
Sizes:  sm = min-height 36px | md = min-height 44px | lg = min-height 52px | xl = min-height 64px
Variants:
  accent: background var(--accent), color #fff (or accent-ink)
  primary: background var(--ink), color var(--bg)
  secondary: background var(--surface), border 1px solid var(--border), color var(--ink)
  ghost: background transparent, color var(--ink)
Press animation: .press class — transform 0.12s ease; :active { transform: scale(0.97); }
Disabled: opacity 0.4, pointer-events: none
```

### `Pill` — Pill/chip with tone
```
Props: tone: 'neutral' | 'accent' | 'ink' | 'glass' | 'warn', children, className?
Tones: neutral = surface-2 bg + border, accent = accent-bg + accent-border, ink = ink bg + bg-color text,
       glass = rgba(255,255,255,0.8) backdrop-blur, warn = warn-bg + warn border
border-radius: var(--r-full)
```

### `SectionLabel` — Uppercase mono section header
```
Props: children, className?
Output: <p class="section-label">{children}</p>
CSS: font-family: var(--font-mono); font-size: 11px; letter-spacing: 0.08em; text-transform: uppercase;
     color: var(--muted); font-weight: 500;
Note: 11px is a component-level override for the SectionLabel capsule only — not a 5th scale size.
```

## Font Loading Contract

Exact implementation in `frontend/app/layout.tsx`:

```typescript
import { Inter, JetBrains_Mono, Noto_Sans_Kannada } from 'next/font/google';

const inter = Inter({
  subsets: ['latin'],
  weight: ['400', '500', '600', '700'],
  variable: '--font-inter',
  display: 'swap',
});

const jetbrainsMono = JetBrains_Mono({
  subsets: ['latin'],
  weight: ['400', '500'],
  variable: '--font-jetbrains-mono',
  display: 'swap',
});

const notoSansKannada = Noto_Sans_Kannada({
  subsets: ['kannada'],
  weight: ['400', '500', '600'],
  variable: '--font-noto-sans-kannada',
  display: 'swap',
});

// Apply to html element:
<html lang="en" className={`${inter.variable} ${jetbrainsMono.variable} ${notoSansKannada.variable}`}>
```

Then in `globals.css`:
```css
body {
  font-family: var(--font-sans);
  font-feature-settings: "cv02", "cv03", "cv04", "cv11";
}
```

This applies globally — admin pages also get Inter, which is acceptable (no adverse effect).

**Anti-pattern:** Do NOT import fonts inside a component function. Must be at module level in `layout.tsx`.

## CSS Architecture Contract

New CSS variables block in `frontend/app/globals.css` — inserted AFTER the `@tailwind` directives, as an additive `:root {}` block. Tailwind classes are unaffected.

**Anti-pattern:** Never add `oklch()` values to `tailwind.config.ts` — Tailwind cannot process oklch at build time. All oklch values stay in `globals.css` CSS variables only.

**Anti-pattern:** Never put CSS variables on `.screen` or a wrapper class — they must be on `:root` to apply globally in the Next.js app context (the design prototype used `.screen` for its phone frame preview; that pattern does not translate).

## State Management Contract (2-Step Report Flow)

Single `"use client"` page at `/report/page.tsx`. State managed via `useState`.

```typescript
type Step = 'photo' | 'category' | 'confirm' | 'success';

interface FormState {
  file: File | null;
  lat: number;
  lng: number;
  locationSource: 'exif' | 'manual_pin';
  gpsConfirmed: boolean;
  category: string;
  severity: string;
  description: string;
  name: string;
  contact: string;
}
```

Step transitions: `photo → category → confirm → success`

`File` objects cannot be serialized — keep all state on a single page. Do not use URL params or `router.push()` state for `File` transfer.
