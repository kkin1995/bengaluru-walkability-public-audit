### Human Verification Required

The automated checks confirm all structural and behavioral requirements are met. The following items require a real device or browser to confirm pixel-faithful design implementation.

**1. Visual design fidelity across all 5 screens**

**Test:** Open `http://localhost:3000` (with frontend running on ui-redesign branch) at 390px viewport width. Navigate through Home → `/report` (Take Photo → Category → Confirm) → Success screen → `/map`. Compare each screen against the CONTEXT.md design spec.
**Expected:** Colors match CSS variable spec (#fafaf9 background, oklch green accent), typography is Inter for body/headings, JetBrains Mono for coordinates and mono labels, Noto Sans Kannada for ಕನ್ನಡ text, warm-toned shadows, correct border radii
**Why human:** CSS visual regression is not automated; jsdom cannot render oklch() colors, evaluate font loading from next/font/google, or measure rendered pixel dimensions

**2. iOS Safari camera UX**

**Test:** On an iPhone, navigate to `/report` on the ui-redesign branch. Tap "Take Photo" label, then separately tap "Upload from Gallery" label.
**Expected:** "Take Photo" (has `capture="environment"`) opens the OS camera directly without a share sheet. "Upload from Gallery" (no capture attribute) opens the photo library picker directly.
**Why human:** `capture="environment"` behavior is device/OS/browser-specific and cannot be simulated in Jest

**3. End-to-end report submission**

**Test:** Submit a complete report (photo with EXIF GPS data → select Damaged category → confirm with medium severity → submit)
**Expected:** SuccessCard renders with a real UUID report ID returned from `POST /api/reports`. Report appears on `/map` as a colored pin.
**Why human:** Requires live Rust backend + PostgreSQL/PostGIS; Jest mocks the fetch call with a fake response

**4. GPS pulsing dot animation on category screen**

**Test:** Capture a photo with EXIF GPS data, proceed to category screen.
**Expected:** GPS pill shows a pulsing green dot (`.pulse` class animating via @keyframes pulse-soft) alongside coordinates in JetBrains Mono. No modal or GPS confirmation step.
**Why human:** CSS animation (@keyframes pulse-soft, 2s ease-in-out infinite) cannot be evaluated in jsdom

**5. Map page filter chip scroll and active state**

**Test:** Open `/map` at 375px width. Swipe the filter chip strip horizontally. Tap a category chip.
**Expected:** No scrollbar is visible (.no-scrollbar hides it). Scrolling works. Active chip background transitions to var(--ink) with white text. Transition feels smooth (0.12s ease via .press class).
**Why human:** scrollbar-width: none and CSS transition behavior require real browser rendering
