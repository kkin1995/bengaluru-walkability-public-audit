## Fixed Issues

### WR-01: Unhandled promise rejection and stuck loading state in `handleFile`

**Files modified:** `frontend/app/report/page.tsx`
**Commit:** 76075d6
**Applied fix:** Changed `handleInputChange` to return early when no file is selected (guard clause), then call `handleFile(file).catch(...)` instead of a bare fire-and-forget call. The `.catch()` handler calls `setPhotoProcessing(false)` and `setError(...)` so the UI never gets stuck in "Processing..." on a corrupt or unreadable image.

---

### WR-02: Blob URL leak in `compressImage` when image fails to load

**Files modified:** `frontend/app/report/page.tsx`
**Commit:** 8004e4f
**Applied fix:** Wrapped the `await new Promise<void>(...)` in `compressImage` in a `try/finally` block. `URL.revokeObjectURL(url)` is now in the `finally` clause, guaranteeing it runs whether the promise resolves or rejects (i.e., whether `img.onerror` fires or not).

---

### WR-03: `activeFilter` state never forwarded to `ReportsMap` — filter UI non-functional

**Files modified:** `frontend/app/map/page.tsx`
**Commit:** 2bcab8e
**Applied fix:** Chose Option B (remove the deferred feature) because `ReportsMap` does not accept a `categoryFilter` prop. Removed: the `FilterChip` interface, the `FILTERS` constant, the `activeFilter` state and `setActiveFilter` setter, the `useState` import (which became unused), and the entire filter chip strip `div` (including its `role="tablist"` and all chip buttons). The filter icon button in the top bar was left in place as a placeholder for when the feature is implemented. The map renders identically without the broken chip strip.

---

### WR-04: `maximumScale: 1` in viewport config disables pinch-to-zoom

**Files modified:** `frontend/app/layout.tsx`
**Commit:** 051a78e
**Applied fix:** Removed the `maximumScale: 1` line from the `Viewport` export. Replaced it with a comment explaining the removal (`// maximumScale removed — allows browser zoom per WCAG 1.4.4`). The remaining viewport properties (`themeColor`, `width`, `initialScale`) are unchanged. Browser default zoom behaviour is now fully restored on iOS and Android.
