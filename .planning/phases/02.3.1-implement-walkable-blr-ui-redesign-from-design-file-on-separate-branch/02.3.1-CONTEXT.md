<domain>
## Phase Boundary

Implement a pixel-faithful Next.js redesign of all citizen-facing screens for the Bengaluru Walkability Audit app, based on the HTML/CSS/JS prototype exported from the claude.ai/design tool. Work is done on a **separate git branch** (e.g. `ui-redesign`) — NOT merged to main unless explicitly requested.

**Screens to implement (5 total):**
1. Home page (`/`)
2. Category picker — Step 1/2 of report flow (`/report` step 1)
3. Confirm & Submit — Step 2/2 of report flow (`/report` step 2)
4. Success screen (post-submit confirmation)
5. Public map view (`/map`)

**Admin pages are explicitly OUT OF SCOPE** for this phase.

</domain>

- Bilingual labels shown everywhere: English primary + Kannada secondary (smaller, 0.72em, 70% opacity)
- Component: `<Bi en="..." kn="..." />` renders stacked flex-column span
- `.bi-kn` class: `font-family: var(--font-kn)`, 0.72em, opacity 0.7

### User Flow (5 screens)
1. **Home** (`/`) → OS camera (system camera, not in-app) → **Category** (step 1) → **Confirm** (step 2) → **Success**
2. **Map** (`/map`) accessible from Home, with floating "Report here" CTA that opens flow
- No in-app camera viewfinder — web app delegates to OS camera via `<input type="file" accept="image/*" capture="environment">`

### Screen 1: Home (`/`)
- Header: brand logo (dark square + pin icon) + "Namma ದಾರಿ" + "Walkable BLR" mono tagline + language toggle (EN · ಕ)
- Hero section: fills space above map — `SectionLabel` "Citizen Audit · ನಾಗರಿಕ", h1 "Fix the footpath.", subtext "Spot a broken, blocked, or missing footpath? Snap it — it goes straight to the public map."
- Map preview: 180px tall, `border-radius: var(--r-lg)`, scatter of 10 colored dots (accent/warn/danger), report count pill ("412 reports"), "Open map →" button
- Primary CTA: accent XL button, full width, camera icon + "Report an issue / ಸಮಸ್ಯೆ ವರದಿ ಮಾಡಿ"
- Sub-text below CTA: "No login · Takes 20 seconds · Anonymous"
- Bottom safe area: `padding-bottom: max(20px, env(safe-area-inset-bottom))`

### Screen 2: Category Picker (Step 1/2)
- **This screen appears AFTER the OS camera is invoked** — user has a photo in hand
- Top section (review row): photo thumbnail (72×72, `border-radius: var(--r-md)`), GPS pill (pulsing dot + coordinates), "Retake" button
- Step indicator: "Step 1 · Category"
- Prompt: "What's the issue? / ಸಮಸ್ಯೆ ಯಾವುದು?"
- Category grid: 2×3 (3 columns), 6 chips, each chip: icon (22px) + bilingual label stacked, min-height 76px, `border-radius: var(--r-md)`
  - Active chip: `background: var(--ink)`, `color: #fafaf9`, checkmark badge overlay
  - Inactive chip: `background: var(--surface)`, `border: 1px solid var(--border)`
- Categories (matching existing enum values):
  - `no_footpath` → "No path" / "ಕಾಲ್ದಾರಿ ಇಲ್ಲ"
  - `broken_footpath` → "Damaged" / "ಹಾಳಾದ"
  - `blocked_footpath` → "Blocked" / "ಮುಚ್ಚಿದ"
  - `unsafe_crossing` → "Crossing" / "ಕ್ರಾಸಿಂಗ್"
  - `poor_lighting` → "Lighting" / "ಬೆಳಕು"
  - `other` → "Other" / "ಇತರ"
- "Continue / ಮುಂದುವರಿಸಿ" CTA: accent XL, disabled (opacity 0.4) until category selected, at bottom

### Screen 3: Confirm & Submit (Step 2/2)
- Header: back arrow + "Confirm & submit" + "Step 2 of 2" + progress dots (2 filled)
- Review card: photo thumbnail + category icon + name (bilingual) + timestamp + edit button
- Location section:
  - Section label "Location · ಸ್ಥಳ" + "GPS confirmed" pulse pill (right-aligned)
  - 120px mini-map with center pin, "Adjust" button (bottom-right)
  - Coordinates row: `12.9762° N, 77.5951° E` (mono) + `±8m` (right)
  - GBA ward card: "GBA" mono badge + "Ward 117 · Shivajinagar" + "Auto-detected · Zone East" + check-circle icon
  - Approx address: "Near MG Road, Shivajinagar"
- Severity section:
  - Section label "Severity · ತೀವ್ರತೆ"
  - 3-column grid, each option: bilingual label, `min-height ~56px`
  - `low` → "Minor / ಸಣ್ಣ" → accent colors when active
  - `medium` → "Moderate / ಮಧ್ಯಮ" → warn colors when active
  - `high` → "Urgent / ತುರ್ತು" → danger colors when active
  - Hint text below grid: shows description of selected severity
- Optional note: section label "Note · ಟಿಪ್ಪಣಿ" + "Optional" tag + textarea placeholder "Add context for the reviewer…"
- Optional contact row: "Add contact for follow-up (private)" with chevron (collapsed)
- Sticky submit button: accent XL full-width "Submit report / ವರದಿ ಸಲ್ಲಿಸಿ" with send icon
- Submit button background: `linear-gradient(to top, var(--bg) 60%, transparent)`

### Screen 4: Success
- Top: close (X) button right-aligned
- Center content: large check circle (accent-bg background), section label "Submitted", h1 "Thank you. It's on the map."
- Body copy: "Your report is **public** on the map immediately. This is a citizen-led project — reports build evidence pressure for the city to act."
- Report ID card (bordered, `border-radius: var(--r-lg)`):
  - "Report ID" section label + "Save for reference"
  - Mono ID: `018F1A2B-3C4D` style
  - Dashed border divider, 2-column grid: Status (dot + "Submitted") | Near (location name)
  - Second dashed divider: GBA badge + "Ward 117 · Shivajinagar" + "Auto-routed" label
- Bottom row: "Share" secondary button (flex 1) + "Report another / ಇನ್ನೊಂದು" primary button (flex 2)

### Screen 5: Public Map (`/map`)
- Full-bleed map (Leaflet, existing ReportsMap component)
- Overlay: all primary actions at top, absolutely positioned
  - Back button (circle, 44px) + search/location bar (flexible, pill shape, "Bengaluru · N reports") + filter button (circle, 44px)
  - Filter chip strip (horizontal scroll, below top bar): "All · N", "Damaged · N", "Blocked · N", "No path · N", "Crossing · N", "Lighting · N"
- Bottom sheet (existing pin selection): photo thumbnail + category + status badge + address + chevron-right
- Floating "Report here" CTA (bottom-right): accent pill button with camera icon

### Walking Ergonomics (locked UX rules)
- All primary actions in bottom 40% of screen
- Minimum 64px tap targets on all CTAs (XL button size)
- 44px minimum for all icon buttons
- GPS trusted silently — only pulsing pill shown (no modal, no confirmation step)
- No required text input — all required fields are tappable (category + severity)

### Component Library (shared primitives)
All to be created as TSX components in `frontend/app/components/ui/`:
- `Bi` — bilingual stacked text span
- `Icon` — inline SVG icon set (stroke icons, 1.75 stroke, 24×24 viewBox)
- `Btn` — button primitive with variant (primary/accent/secondary/ghost) and size (sm/md/lg/xl)
- `Pill` — pill/chip with tone (neutral/accent/ink/glass/warn)
- `SectionLabel` — uppercase mono section header
- `press` CSS class: `transition: transform 0.12s ease` + `:active { transform: scale(0.97) }`

### Icon Names Required
camera, map, pin, arrow_right, arrow_left, check, check_circle, close, image, flash, flip, crosshair, edit, send, chevron_right, chevron_down, share, grid, list, filter, globe, menu, shield, mic, cat_no_path, cat_broken, cat_blocked, cat_crossing, cat_lighting, cat_other, cat_ramp, cat_encroach

### Branch Strategy
- All work done on branch `ui-redesign` (create from `main` or current `phase-02.3-uat-fixes`)
- **Do not merge to main** — phase goal is to have a reviewable branch

### CSS Architecture
- New file: `frontend/app/globals-redesign.css` OR update `frontend/app/globals.css` with the new CSS variables (non-breaking — CSS variables do not affect existing component rendering)
- The design system lives entirely in CSS custom properties — existing Tailwind classes are unaffected

### Existing Components — Reuse vs. Replace
- `ReportsMap` → reuse as-is for `/map` page, wrap in new layout
- `PhotoCapture` → the file-picker logic is retained; UI shell gets redesigned
- `CategoryPicker` → UI fully replaced with 2×3 grid chips
- `BilingualText` → existing component, check if it matches new `Bi` pattern
- `SubmitSuccess` → UI fully replaced
- `ReviewStrip` → retained for confirm screen review card section

### Claude's Discretion
- Exact Next.js file structure for the new screens (page.tsx vs nested routes)
- How to thread state between category screen and confirm screen (URL params vs context vs localStorage)
- Whether to create a dedicated layout for the report flow or nest within root layout
- Animation/transition between steps (keep minimal — not specified in design)
- How to handle GPS failures gracefully (show manual-pin fallback — not fully designed)
