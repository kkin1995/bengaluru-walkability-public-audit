<objective>
Close the 3 confirmed-bug UAT gaps from 03-UAT.md (tests 3, 4, 5) that are blocking Phase 03 sign-off.

Root causes (both from diagnostic commit 3683b79):
- **Tests 4 + 5 (HTTP 500):** `backend/migrations/011_analytics_mv.sql` defines `refresh_public_stats_mv()` using `REFRESH MATERIALIZED VIEW CONCURRENTLY public_stats_mv`, but `idx_public_stats_mv` is built on the constant expression `(1)` — PostgreSQL refuses CONCURRENTLY when no real-column unique index exists. Every mutation that touches the `reports` table (assign-org, resolve) fires this trigger, which then panics at the DB level. Fix: new migration 012 that `CREATE OR REPLACE FUNCTION refresh_public_stats_mv()` replacing CONCURRENTLY with a plain `REFRESH MATERIALIZED VIEW`.
- **Test 3 (stale filter labels):** `ReportsTable.tsx:611-626` computes filter chip counts and keys against deleted enum values `"submitted"` and `"under_review"`. Since migration 008 renamed those to `"open"` and `"acknowledged"`, no report ever matches these predicates — counts are always 0 and labels read "SUBMITTED" / "REVIEW". Fix: update counts, chip definitions, and filter predicate to current 6-value enum. Also update the card-view status dot colour ternary (lines 265-266) which still references the deleted CSS tokens `--status-submitted` / `--status-review`.
</objective>

    ```sql
    -- Migration 012: Fix refresh_public_stats_mv() — drop CONCURRENTLY
    --
    -- Migration 011 defined the trigger function with REFRESH MATERIALIZED VIEW
    -- CONCURRENTLY, but idx_public_stats_mv is a constant-expression index (1)
    -- which PostgreSQL refuses for CONCURRENTLY refreshes.  Every mutation on
    -- the reports table (assign-org, resolve) fired the trigger and returned
    -- HTTP 500.  This migration replaces the function body in-place.
    --
    -- Trade-off: plain REFRESH holds ShareUpdateExclusiveLock on public_stats_mv
    -- for the duration of the refresh.  At MVP scale (<10k rows) this is <50ms
    -- and does not block readers.  CONCURRENTLY can be re-introduced if a
    -- real-column unique index is added in a later migration.

    CREATE OR REPLACE FUNCTION refresh_public_stats_mv()
    RETURNS TRIGGER LANGUAGE plpgsql AS $$
    BEGIN
        REFRESH MATERIALIZED VIEW public_stats_mv;
        RETURN NULL;
    END;
    $$;
    ```
