# Phase 02.4 Plan 03: Self-Hosted Deployment Runbook Summary

**One-liner:** Self-contained, 458-line deployment runbook at the repository root covering every step to stand up the Arch Linux + Cloudflare Tunnel + GitHub Actions production stack from scratch.

## What Was Built

`DEPLOYMENT.md` at the repository root — a 9-section numbered runbook structured so a developer (or future-Claude) can follow it top to bottom without consulting any other source:

1. **Overview** — architecture explanation, ASCII diagram (Citizen → Vercel → Cloudflare edge → cloudflared → nginx → backend → db), "what runs where" table, and why Cloudflare Tunnel was chosen
2. **Prerequisites** — host requirements and list of tools installed during the runbook
3. **Arch Linux Desktop Setup** — Docker + Compose plugin install, docker group membership, optional log rotation config
4. **Cloudflare Tunnel Setup** — AUR install, `cloudflared tunnel login`, `cloudflared tunnel create walkability-prod`, `/etc/cloudflared/config.yml` template with the correct ingress rule (`service: http://localhost:80`), DNS record creation (both auto and manual), systemd service install
5. **Production Environment Variables** — table of all 8 vars with generation commands and an example `.env` file
6. **First Manual Deploy** — clone, `.env` placement, canonical first-deploy command, local + public health verification
7. **GitHub Actions Self-Hosted Runner** — GitHub UI token generation, dedicated `gh-runner` user creation, runner config with `walkability-prod` label, `svc.sh install + start`, GitHub UI verification
8. **Ongoing Operations** — reference table of common operations with exact commands
9. **Troubleshooting** — 7-row table covering tunnel connectivity, docker permissions, runner offline, deploy health failure, tunnel 502, admin login loop, missing production environment
