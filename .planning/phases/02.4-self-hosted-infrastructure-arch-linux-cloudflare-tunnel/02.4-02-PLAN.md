<objective>
Replace the current Railway-based deploy workflow with a three-job pipeline that deploys the backend to the Arch Linux desktop via a self-hosted GitHub Actions runner, then smoke-tests the public Cloudflare tunnel URL and Vercel frontend.

Purpose: Railway is decommissioned. Every push to main must now build the backend image, restart `db + backend + nginx` via the new Compose override, and verify both the public API (via the Cloudflare tunnel) and the Vercel frontend before declaring deploy success.

Output: A rewritten `.github/workflows/deploy.yml` with jobs `ci` → `deploy` → `smoke-test`. The existing `ci.yml` is reused via `workflow_call` and is NOT modified.
</objective>

GitHub Actions secrets the deploy job MUST consume (passed to docker compose via env at the job level):
- POSTGRES_PASSWORD — postgres container password
- JWT_SECRET — backend session token signing key (min 32 chars)
- ADMIN_SEED_EMAIL — initial super-admin email
- ADMIN_SEED_PASSWORD — initial super-admin password (min 12 chars)

GitHub Actions variables the workflow MUST consume:
- vars.BACKEND_URL — public Cloudflare tunnel URL, e.g. https://api-walkability.kinariwala.com
- vars.FRONTEND_URL — Vercel frontend URL, e.g. https://staging-walkability.kinariwala.com
- vars.CORS_ORIGIN — origin string the backend uses for CORS, must equal FRONTEND_URL with no trailing slash

The COOKIE_SECURE env var is hard-coded to "true" in the workflow (Cloudflare terminates TLS, so cookies always travel over HTTPS).

Runner labels: the self-hosted runner installed in Plan 03 will be labeled `self-hosted`, `linux`, and `walkability-prod`. The deploy job MUST require all three labels.

Compose command (canonical, must be used verbatim in both build and up steps):
- Build: `docker compose -f docker-compose.yml -f docker-compose.server.yml build backend`
- Up: `docker compose -f docker-compose.yml -f docker-compose.server.yml up -d --remove-orphans db backend nginx`
- Status (for failure diagnostics): `docker compose -f docker-compose.yml -f docker-compose.server.yml ps`

      4. `name: Wait for local health` — a bash `run:` block that loops 6 times: each iteration does `curl -sf --max-time 5 http://localhost/health` and exits 0 on first 2xx; sleeps 10 between attempts; on the 6th failure prints `docker compose -f docker-compose.yml -f docker-compose.server.yml ps` and `docker compose -f docker-compose.yml -f docker-compose.server.yml logs --tail=50 backend nginx` then exits non-zero.

    The shell loop (step 4) must look like (use a literal pipe-block string `|` in YAML):
    ```
          - name: Wait for local health
            run: |
              for i in 1 2 3 4 5 6; do
                if curl -sf --max-time 5 http://localhost/health; then
                  echo ""
                  echo "Local health OK on attempt $i"
                  exit 0
                fi
                echo "Attempt $i/6 failed, retrying in 10s..."
                sleep 10
              done
              echo "Local health check failed after 6 attempts"
              docker compose -f docker-compose.yml -f docker-compose.server.yml ps
              docker compose -f docker-compose.yml -f docker-compose.server.yml logs --tail=50 backend nginx || true
              exit 1
    ```

    Job 3 — `smoke-test`:
    - `name: "Smoke test"`
    - `needs: deploy`
    - `runs-on: ubuntu-latest`
    - Steps:
      1. `name: "Health check — Cloudflare tunnel backend (with retry)"` — bash loop, 5 attempts × 15s sleep, hitting `${{ vars.BACKEND_URL }}/health` with `curl -sf --max-time 10`; succeed on first 200; fail with non-zero after 5 misses with a printed message.
      2. `name: "API check — reports endpoint"` — `curl -sf --max-time 10 "${{ vars.BACKEND_URL }}/api/reports"` piped through `head -c 200` (echo the truncated body for log visibility); fails non-zero on curl error.
      3. `name: "Frontend check — Vercel"` — capture HTTP status: `status=$(curl -sf -o /dev/null -w "%{http_code}" --max-time 15 "${{ vars.FRONTEND_URL }}")` then assert `[ "$status" -eq 200 ]` and echo the status; non-200 fails the step.

    YAML formatting rules:
    - 2-space indentation
    - Use block scalars (`|`) for multi-line shell `run:` blocks
    - Quote env values that look like booleans (e.g., `COOKIE_SECURE: "true"`) to prevent YAML from coercing them
    - No `if: secrets.X != ''` gating — these secrets are now mandatory; absence must fail the deploy fast

    Forbidden tokens (must not appear anywhere in the new file): `RAILWAY`, `Railway`, `railway`, `VERCEL_STAGING_URL` (literal hard-coded URL — replaced by `vars.FRONTEND_URL`).
