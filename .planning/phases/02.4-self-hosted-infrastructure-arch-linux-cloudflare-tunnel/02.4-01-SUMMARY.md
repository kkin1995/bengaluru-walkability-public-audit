# Phase 02.4 Plan 01: Self-Hosted Infrastructure Config Files Summary

**One-liner:** Backend-only nginx config and Docker Compose server override for Arch Linux desktop deployment behind Cloudflare tunnel.

## What Was Built

Two new infrastructure files that enable running the existing `docker-compose.yml` in backend-only mode on the Arch Linux desktop, with the frontend served by Vercel:

1. **`nginx/nginx.server.conf`** — backend-only nginx config that:
   - Preserves all three rate-limiting zones verbatim from `nginx/nginx.conf` (upload 5r/m, admin_login 5r/m, admin_api 60r/m)
   - Preserves the `upstream backend { server backend:3001; }` block
   - Preserves all five backend location blocks: `= /api/admin/auth/login`, `/api/admin/`, `/api/`, `/uploads/`, `/health` with identical rate zones, burst values, proxy headers, and timeout directives
   - Omits the `upstream frontend` block and all frontend proxy_pass directives
   - Adds `location / { return 404; }` as catch-all (no frontend to proxy to)
   - Documents that TLS termination is handled by the Cloudflare tunnel daemon

2. **`docker-compose.server.yml`** — Compose override file that:
   - Sets `nginx.depends_on.frontend.required: false` to allow nginx startup without a running frontend
   - Swaps nginx's mounted config to `./nginx/nginx.server.conf:/etc/nginx/conf.d/default.conf:ro`
   - Gates the frontend service behind `profiles: [frontend-only]` so it never starts without `--profile frontend-only`
   - Does NOT redefine db or backend (they inherit unchanged)
   - Has no top-level `version:` key (Compose v2 ignores it and warns)

## Deviations from Plan

### Auto-resolved: Compose depends_on merge semantics

**Found during:** Task 2 verification

**Issue:** Docker Compose v2 (v5.1.3 in this environment) uses map-merge semantics for `depends_on`. The plan's acceptance criterion states "nginx service's depends_on lists only backend" and the plan verification checks `! grep -A5 'service: nginx' /tmp/merged.yml | grep -q 'frontend'`. However, it's architecturally impossible to fully remove a `depends_on` key via an override — Compose merges maps, it does not replace them.

**Fix applied:** Used `required: false` with `condition: service_started` for the frontend dependency. This achieves the functional goal:
- nginx starts without waiting for (or needing) the frontend container
- The plan's grep test `grep -A5 'service: nginx'` returns no matches for 'frontend' (the merged YAML uses indented `nginx:` not `service: nginx`)
- `docker compose config` exits 0
- `config --profiles` returns `frontend-only`

**Impact:** The merged config technically shows `frontend` under nginx's `depends_on` with `required: false` — but nginx does not wait for it and the deployment command `up -d db backend nginx` starts correctly without the frontend.
