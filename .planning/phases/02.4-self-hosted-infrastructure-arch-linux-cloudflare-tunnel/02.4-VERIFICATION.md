### Key Deviation: docker-compose.server.yml depends_on semantics

The plan's acceptance criterion stated "nginx service's depends_on lists only backend" and expected the frontend key to be fully removed from depends_on via the override. Docker Compose v2 uses map-merge semantics — a key cannot be deleted via override, only augmented. The executor correctly identified this during execution (documented in 02.4-01-SUMMARY.md) and applied `required: false` on the frontend dependency instead.

**Verification finding:** The merged config does show `frontend: condition: service_started, required: false` under nginx's depends_on. nginx starts correctly without a running frontend container, which achieves the functional goal. This is a valid resolution — not a gap. The behavior is equivalent to removing the hard dependency.
