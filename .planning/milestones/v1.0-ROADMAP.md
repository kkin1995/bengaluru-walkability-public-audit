## Overview

The citizen-facing submission and admin dashboard already existed at milestone start. v1.0 closes the loop between citizen reports and government action: grounding every report in a ward (Phase 1), hardening the platform against abuse before public launch (Phase 2), building the government triage workflow that makes GBA want to use the platform (Phase 3), and surfacing aggregated data as exports and public analytics that make the platform policy-relevant (Phase 4).

Ten insertion phases were added mid-milestone for urgent security hardening, staging deployment, UAT bug fixes, UI redesign, self-hosted infrastructure, and gap closure — none were in the original roadmap.

## Milestone Summary

**Key Decisions Made:**
- ST_Multi() wraps every ward INSERT so all boundary rows are MULTIPOLYGON (avoids mixed-type column violations in PostGIS)
- org_type stored as TEXT + CHECK constraint, not ENUM — allows extending allowed values without ALTER TYPE migration
- org_id NOT stored in JwtClaims — fetched from DB per request to avoid token re-issue on org reassignment
- SHA256 hash computed from raw image bytes BEFORE strip_exif — re-uploads of same photo match regardless of client-side EXIF handling
- SameSite=None cookie required for Vercel+Railway cross-domain auth
- Photo hash match returns fake HTTP 200 (same as honeypot) — bots and double-tapping users get no error signal
- alpine tar czf used for uploads volume backup (no rsync on alpine)
- Plain REFRESH MATERIALIZED VIEW accepted over CONCURRENTLY — constant-expression index incompatible with CONCURRENTLY
- geohash precision=6 gives ~1.2km × 0.6km cells for anti-flood rate limiting
