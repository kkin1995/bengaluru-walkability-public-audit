## v1 Requirements — All Satisfied

### Ward & Spatial Routing

- [x] **WARD-01**: Reports are automatically assigned to the correct Bengaluru ward via PostGIS `ST_Within` query at submission time — **Phase 1** ✓ v1.0
- [x] **WARD-02**: An `organizations` table stores the flexible GBA → corporation → ward office hierarchy as data (not hardcoded), with self-referential parent_id — **Phase 1** ✓ v1.0
- [x] **WARD-03**: Each admin user is assigned to an organization, controlling which reports they see and can act on — **Phase 1** ✓ v1.0 (org_id fully populated via Phase 04.1 migration)
- [x] **WARD-04**: Ward boundary data for Bengaluru is imported into PostGIS and kept as the spatial source of truth for routing — **Phase 1** ✓ v1.0

### Security Hardening (Phase 02.1)

- [x] **SEC-01**: `submitter_name` is absent from public API responses at the struct level (compile-time guarantee via `ReportResponse`) — **Phase 02.1** ✓ v1.0
- [x] **SEC-02**: Single canonical `require_role` from `middleware::auth` with admin-is-superset semantics — no local duplicates in handlers — **Phase 02.1** ✓ v1.0
- [x] **SEC-03**: No `.unwrap()` on `serde_json::to_value` in production handler paths — all serialization errors produce `AppError::Internal` — **Phase 02.1** ✓ v1.0
- [x] **SEC-04**: `COOKIE_SECURE` defaults to `true` in production `docker-compose.yml`; explicit `false` override required for local dev — **Phase 02.1** ✓ v1.0
- [x] **SEC-05**: nginx CSP `style-src` has no `unsafe-inline`; TLS termination expectations documented in nginx config comments — **Phase 02.1** ✓ v1.0
- [x] **SEC-06**: Admin login page never surfaces raw server error messages (A07 hardening); generic messages for 401/429/5xx — **Phase 02.1** ✓ v1.0
- [x] **SEC-07**: Password validation threshold aligned frontend/backend at 12 characters; CI runs `cargo audit` and `npm audit --audit-level=high` on every PR — **Phase 02.1** ✓ v1.0

- [x] **STAGING-05**: All `cargo test` and `npm run build` pass with cross-domain auth changes in place — **Phase 02.2** ✓ v1.0

### Self-Hosted Infrastructure (Phase 02.4)

- [x] **INFRA-01**: The Rust/Axum backend and PostGIS database run via `docker compose` on the Arch Linux desktop using `docker-compose.yml` + `docker-compose.server.yml` override — **Phase 02.4** ✓ v1.0
- [x] **INFRA-02**: A Cloudflare tunnel (`cloudflared` systemd service) routes public HTTPS traffic to the desktop `nginx:80`, and `curl https://<tunnel-url>/health` returns `{"status":"ok"}` from the internet — **Phase 02.4** ✓ v1.0
- [x] **INFRA-03**: A GitHub Actions self-hosted runner on the desktop executes the deploy job on every push to `main` — building and restarting services via `docker compose` — with zero manual SSH steps — **Phase 02.4** ✓ v1.0
- [x] **INFRA-04**: The Vercel-hosted Next.js frontend successfully calls the backend through the Cloudflare tunnel URL (`NEXT_PUBLIC_API_URL` updated, Vercel redeploy triggered) — **Phase 02.4** ✓ v1.0
- [x] **INFRA-05**: The full admin login + report submission flow works end-to-end across the Vercel frontend ↔ Cloudflare tunnel ↔ desktop backend boundary — **Phase 02.4** ✓ v1.0

### UAT Bug Fixes (Phase 02.3)

- [x] **BUG-02**: On iOS Safari, "Take Photo" opens camera directly and "Upload from Gallery" opens photo library — no shared action sheet — **Phase 02.3** ✓ v1.0
- [x] **UX-01**: Admin reports table has a right-edge fade gradient on mobile (md:hidden) indicating horizontal scroll — **Phase 02.3** ✓ v1.0

### Anti-Abuse & Data Quality

- [x] **ABUSE-01**: Report submission is rate-limited at the application layer (max 2 reports per IP per geohash-6 cell per hour) using `governor` crate — **Phase 2** ✓ v1.0
- [x] **ABUSE-02**: A honeypot hidden field silently discards submissions from bots without any error message shown to human users — **Phase 2** ✓ v1.0
- [x] **ABUSE-03**: Reports within 50m of an existing open report of the same category are flagged as `potential_duplicate` with a `duplicate_count` increment on the original — **Phase 2** ✓ v1.0
- [x] **ABUSE-04**: When multiple users submit reports from the same location (within 50m, same category), `duplicate_confidence` is set to `high` — **Phase 2** ✓ v1.0
- [x] **ABUSE-05**: Exact duplicate photos (same SHA256 hash) are silently rejected at upload — **Phase 2** ✓ v1.0
- [x] **ABUSE-06**: `duplicate_count` on a report is visible in the admin triage queue as a severity indicator — **Phase 2** ✓ v1.0

### Government Workflow

- [x] **WFLOW-01**: Reports support an extended status lifecycle: `Open → Acknowledged → Assigned → In Progress → Resolved → Closed` — **Phase 3** ✓ v1.0
- [x] **WFLOW-02**: Every status transition is recorded in `status_history` with timestamp and acting admin user ID — **Phase 3** ✓ v1.0
- [x] **WFLOW-03**: Admin can assign a report to an organization (corporation or ward office) — **Phase 3** ✓ v1.0
- [x] **WFLOW-04**: Admin can add resolution notes when closing a report — **Phase 3** ✓ v1.0
- [x] **WFLOW-05**: Admin can upload a resolution photo (after-photo) when marking a report as Resolved — **Phase 3** ✓ v1.0

### Public Map

- [x] **MAP-01**: Public map pins are color-coded by report status (distinct colors for Open, In Progress, Resolved) — **Phase 3** ✓ v1.0
- [x] **MAP-02**: A heatmap layer on the public map shows issue density by geographic area, togglable by the user — **Phase 4** ✓ v1.0
- [x] **MAP-03**: Report status is visible in the popup when a map pin is clicked — **Phase 3** ✓ v1.0

### Data Export

- [x] **EXPORT-01**: Admin can export filtered reports as CSV (filters: ward, category, status, date range); CSV uses DD/MM/YYYY date format and includes ward name column — **Phase 4** ✓ v1.0
- [x] **EXPORT-02**: Admin can export filtered reports as GeoJSON FeatureCollection (streaming response, no memory buffering) — **Phase 4** ✓ v1.0
- [x] **EXPORT-03**: A public unauthenticated GeoJSON endpoint returns all reports with coordinates rounded to 3 decimal places and no PII fields — **Phase 4** ✓ v1.0

### Public Analytics

- [x] **ANALYTICS-01**: A public stats page shows total report count, resolved count, and top 3 issue categories — updated from a materialized view — **Phase 4** ✓ v1.0
- [x] **ANALYTICS-02**: Admin analytics view shows top 10 wards by unresolved report count — **Phase 4** ✓ v1.0
- [x] **ANALYTICS-03**: Admin analytics view shows resolution rate per corporation (resolved / total reports in their wards) — **Phase 4 + Phase 04.1** ✓ v1.0 (wards.org_id migration + ::float8 cast fix)
- [x] **ANALYTICS-04**: Admin analytics view shows trend chart: reports submitted per week over the last 12 weeks, filterable by category — **Phase 4** ✓ v1.0
- [x] **ANALYTICS-05**: Admin analytics map shows ward choropleth: ward fill color by unresolved report density — **Phase 4** ✓ v1.0

### Phase 04.1 Non-Functional Requirements (gap-closure)

- [x] **NF-04.1-A**: Migration 014 (`014_link_wards_to_organisations.sql`) links all 369 ward rows to their parent corporation organization via `ILIKE` on `wards.corporation` — idempotent (`WHERE org_id IS NULL`) — **Phase 04.1** ✓ v1.0
- [x] **NF-04.1-B**: SQL-string unit tests in `backend/tests/analytics_tests.rs` guard against pattern drift between the migration UPDATE expression and the `get_org_for_ward` ILIKE query, and assert that `CORP_ANALYTICS_SQL` uses a `::float8` cast — **Phase 04.1** ✓ v1.0
- [x] **NF-04.1-C**: The `AdminReport` TypeScript interface in `frontend/app/admin/lib/adminApi.ts` declares `corporation: string | null` as a non-optional typed field; `ReportsTable.tsx` CORP column accesses `report.corporation` directly without `as unknown as` unsafe casts — **Phase 04.1** ✓ v1.0
